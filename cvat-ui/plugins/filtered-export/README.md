# タグ条件を指定したデータセットのエクスポート

タスクとプロジェクトのActionsに「条件を指定してエクスポート」を追加します。同じ画面内のダイアログで画像を選び、既存のCVAT形式変換とエクスポートキューを利用します。通常のエクスポートとアノテーション画面の表示フィルターは変更しません。

## 利用手順

編集内容を保存してから、タスクまたはプロジェクトのActionsを開きます。タグ条件は「いずれかがある」「すべてある」「一つもない」「どのタグもない」「タグで絞り込まない」から選択できます。複数タスクの一覧選択には対応せず、クリックしたタスクまたは一つのプロジェクトを対象にします。

「一つもない」は選択したタグがない画像を選び、別のタグがある画像を含みます。「どのタグもない」はすべてのタグを調べます。矩形やSegmentationの有無は、この条件に影響しません。削除済みフレームは出力しません。

フレーム番号は0から始まるタスク内の番号です。元動画の開始フレームや取り込み時の間引きから算出される番号ではありません。開始と終了を含み、終了の空欄は最後までを意味します。プロジェクトでは各タスクに同じ範囲を適用します。抽出間隔は指定した開始番号を基準に適用し、その結果とタグ条件の共通部分を出力します。条件に一致した画像を数えて何枚おきかを選ぶ機能ではありません。

出力形式を選び、「対象件数を確認」でタスク別の件数を確認した後にエクスポートします。画像を含めるか、アノテーションだけにするかを選択できます。完了状態とファイルは既存のRequests画面で確認します。受け付け後はダイアログを閉じられます。

選択画像のアノテーションは、出力形式が表現できる範囲で保持します。「出力からすべてのタグを除外する」は任意です。この指定は出力用のメモリ上のデータだけを変更し、画像の選択条件や保存済みデータは変更しません。ITGformatはタグを表現できないため、この指定を必須にしています。ITGformatの既存の形状制限はそのまま適用します。

## 有効化と無効化

ルートの`.env`の`CVAT_CLIENT_PLUGINS`に`plugins/filtered-export`をコロン区切りで追加します。既存の指定は残してください。以下は既存の独立したUI拡張と併用する例です。

```dotenv
CVAT_CLIENT_PLUGINS=plugins/frame-navigation-filter:plugins/selective-ai:plugins/filtered-export
```

既存の`cvatctl`の手順でサーバーとUIをビルドして起動します。今回は新しいPythonモジュールを含むため、UIだけでなくサーバーとエクスポートワーカーも同じコミットから再作成する必要があります。

```sh
./cvatctl build
./cvatctl up
```

UIを直接開発する場合は`CLIENT_PLUGINS`を使います。既存の拡張管理は任意の追加UIプラグインを保持するため、`CVAT_EXTENSIONS`の名前一覧や管理スクリプトは変更しません。マージだけでは既存の実行環境には反映されません。

プラグインの指定を外してUIを再ビルドするとメニューが消えます。新APIはこのコミットのサーバーに残ります。APIも除去する場合は、この変更を含まないコミットからサーバーとワーカーを再ビルドします。新しいDBテーブル、マイグレーション、依存パッケージ、追加サービスはありません。

## 実装範囲

既存ファイルの変更は`cvat/urls.py`のAPI登録1行です。実装は`cvat/apps/dataset_manager/filtered_export/`とこのUIプラグインに分離しています。既存の形式変換、API実装、キュー管理、権限定義、共通UI部品は書き換えません。実行時の関数置換もありません。

画像の抽出には既存の`TaskData.included_frames`を使用します。プロジェクト用の小さな派生クラスはタスクごとに選択フレームを渡し、名前の重複回避、subset、フレーム番号の変換を既存の`ProjectData`に任せます。画像を全件出力してからZIPの一部を削除する方式ではありません。

Trackのキーフレームを事前に削除せず、既存の補間処理で選択フレーム上の形状を得ます。出力は画像単位です。動画のTrack構造を維持した疎な動画エクスポートではありません。形式によってはTrack IDなどの情報が出力されないことがあります。

プレビューは保存済みデータを読みます。画面で条件を変更すると、UIはプレビュー結果を破棄します。サーバーはタグ、タスク構成、削除フレーム、更新日時などの変更をエクスポート受付時とワーカー開始時に検出すると、再プレビューを要求します。出力処理は既存のrepeatable-readトランザクションを利用します。更新日時の管理はCVATの通常の更新経路を前提とし、DBを直接変更する操作は対象外です。

プレビューとエクスポートは既存の`initiate_dataset_export`アクション名とTaskPermissionまたはProjectPermissionを使います。各処理で`get_object()`による権限確認を行い、ダウンロードは既存の`download_dataset`権限とダウンローダーを利用します。追加でリクエストの利用者IDを検証します。表示名の似たタグや他のプロジェクトのラベルIDを代用しません。

ブラウザーはCVATの設定済みAxiosインスタンスを使用し、組織をリクエストに固定します。利用者または組織の変更でダイアログを破棄します。POSTは自動再送しません。応答が失われた場合はRequestsを確認するよう表示します。既にサーバーが受け付けた出力は、ブラウザー側の破棄では取り消しません。

通常の出力と抽出条件ごとの出力を混同しないよう、条件、リビジョン、利用者、出力形式、画像とタグの指定を識別子に含めます。既存のリクエストID形式を変更しないため、リクエストID内の形式名に`filtered`とSHA-256を付加します。Requests画面の形式欄にもこの識別子が表示されます。実際の形式変換に渡す形式名は元のままです。キャッシュ名には同じ識別子を付加し、既存の期限切れ削除が解釈できる命名規則を保ちます。

## 対応範囲と制限

2Dの画像と動画を取り込んだタスク、およびそのプロジェクトが対象です。ジョブ単位、複数プロジェクト、音声、3D、GT-pool、クラウドストレージへの直接出力には対応しません。プロジェクト内のメディア未設定タスクは通常のプロジェクト出力と同じく対象外です。メディアのある非対応タスクが混在する場合はエラーにします。

対応形式はCVAT for images 1.1、COCO 1.0、YOLO 1.1、Ultralytics YOLOのDetection、Segmentation、Oriented Bounding Boxes、Poseの各1.0、およびITGformat 1.0です。実際に登録されて有効な形式だけを表示します。`included_frames`を経由しないCVAT for videoなどは、意図しないフレームを含めないよう対象外にしています。

タグの属性値、形状ラベルによる絞り込み、任意の論理式には対応しません。プレビューは件数を返し、個別画像の手動選択には対応しません。APIのプレビュー処理は同期処理です。大規模プロジェクトではDB読み出しとアノテーションの読込みに時間がかかり、HTTPタイムアウトになる可能性があります。出力本体は通常のエクスポートキューで動きます。ネイティブの動画フレーム読出しが非選択フレームをデコードする場合もあり、出力数に比例した高速化を保証しません。

## 拡張API

以下の`tasks`は`projects`にも置き換えられます。既存SDKの公開APIを変更しないため、この拡張APIは生成OpenAPIスキーマには含めません。

```text
GET  /api/filtered-export/tasks/{id}/options
POST /api/filtered-export/tasks/{id}/preview
POST /api/filtered-export/tasks/{id}/export
GET  /api/filtered-export/tasks/{id}/download?rq_id=...
```

POSTのクエリには`format`、`save_images`、`location=local`、`use_default_location=false`と通常の組織指定を渡します。本文の例は以下です。`expected_revision`はプレビューでは省略し、エクスポートではプレビュー応答の`revision`を渡します。下記の値は説明用です。

```json
{
  "filter": {
    "mode": "any",
    "tag_ids": [123],
    "start": 0,
    "stop": null,
    "step": 1
  },
  "omit_tags": false,
  "expected_revision": "<preview response revision>"
}
```

出力受付は`202`と`rq_id`を返します。既に同じ処理が進行中の場合は`409`と既存の`rq_id`を返します。状況確認とダウンロードURLの取得には既存の`/api/requests/{rq_id}`を使用します。

## 検証

以下は外部サービスなしで実行する単体テストです。Pythonは標準ライブラリだけを使い、JavaScriptはリポジトリのTypeScript依存関係を使用します。

```sh
python -m unittest discover -s tests/filtered_export -v
node --test cvat-ui/plugins/filtered-export/tests/*.test.cjs
npx tsc --noEmit --strict --target es2022 --lib es2022,dom \
  cvat-ui/plugins/filtered-export/src/ts/api.ts
python -m compileall -q cvat/apps/dataset_manager/filtered_export
```

Python 39件とNode 10件が通過しました。Pythonのサービスとリクエスト管理のテストはCVATとDjangoの境界をテスト用の代替実装に置き換え、抽出条件、空選択、元データ不変、プロジェクトのフレーム分離、変更検出、キャッシュ分離、受付とダウンロードへの委譲を検証します。NodeはHTTP引数、組織変更、再送抑止、メニュー登録を検証します。独立した型検査は`api.ts`を対象とし、TSXの確認はトランスパイル時の構文検査です。

CVAT全体のビルド、実ブラウザー、実DB、Redis、OPAとの権限結合、およびネイティブ形式変換の出力ファイルを使った結合テストは未実施です。これらの単体テストを、その代わりと扱わないでください。

レビュー環境では使い捨てタスクに複数タグ、タグのない画像、矩形、Mask、離れたキーフレームを持つTrackを用意し、各条件のプレビュー件数とZIP内の画像数を照合してください。CVAT images、COCO、YOLO、ITGformatそれぞれで非選択画像とそのアノテーションが含まれないことを確認します。開始フレームと取り込み間隔を持つ動画、削除済みフレーム、複数subset、同名画像を持つ複数タスク、0件のタスクを含むプロジェクトでも確認が必要です。

権限の確認では閲覧不可の利用者、エクスポート不可の利用者、他組織、別利用者の`rq_id`を使用し、プレビューと出力とダウンロードが拒否されることを確認してください。プレビュー後のタグ編集、キュー待機中のタスク編集、通常出力との同時実行、期限切れキャッシュ、通信切断も確認対象です。通常のエクスポートと既存プラグインが変わらないことも確認します。

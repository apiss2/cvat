# JSONからタスク用ガイドを取り込む

## 操作

対象プロジェクトの既存のデータセット取り込み画面で `Task guide JSON 1.0` を選び、JSONファイルを指定します。標準のアップロード、インポートキュー、Requestsを利用します。新しい画面やAPIは追加しません。タスクとジョブへの取り込みでは、この形式を選んでもエラーになります。

PR11のDICOM取り込みで画像や動画を登録した後に使用します。取り込み先は各タスクの標準 `AnnotationGuide` です。プロジェクト用ガイド、画像、動画、ラベル、Tag、Shape、Trackは変更しません。新規タスクも作成しません。

サーバーとインポートワーカーにこの変更を含めて再ビルドしてください。取り込み形式はバックエンドに常時登録されます。PR10の `task_context` UIプラグインはタスク詳細とInfoでの表示を選択するもので、取り込み形式の有効化スイッチではありません。

## 入力の構造

`records` 配列を持つオブジェクト、またはレコード配列を直接受け取ります。各レコードは `input` と `result` を持ちます。処理は機械的で、翻訳、医学的な要約、部位辞書、外部サービスへの送信は行いません。

```json
{
  "records": [
    {
      "input": {
        "patient_id": "P1",
        "study_instance_uid": "1.2.3",
        "study_date": "20250101",
        "parsed_patient_age": "25Y",
        "patient_sex": "M",
        "modality": "CT"
      },
      "result": {
        "extracted": {
          "part": ["brain"],
          "history": ["History text"],
          "objective": "Objective text",
          "findings": "English findings",
          "impression": "English impression"
        },
        "findings_ja": "所見本文",
        "impression_ja": "診断本文"
      }
    }
  ]
}
```

識別子は文字列です。`study_uid` は `study_instance_uid`、`uid` は `patient_id`、`date` は `study_date` の別名として受け付けます。同じ項目の別名が併存し、値が異なる場合は拒否します。日付は `YYYYMMDD` または `YYYY-MM-DD` です。

## タスクの照合

省略されていないStudyInstanceUIDの完全一致を使います。PatientIDや日付だけの照合、部分一致、SOP UID末尾8文字からの推定は行いません。接頭辞の指定は不要です。

静止画ではPR11の `{prefix}_{PatientID}_{StudyDate}_{StudyInstanceUID}` というタスク名を認識します。PatientIDのファイル名用置換もPR11と合わせています。JSONにPatientIDや日付があれば、タスク名との一致も確認します。

動画のタスク名にはStudyInstanceUIDが含まれないため、PR11のTagアノテーション `DicomTag` を参照します。使用する属性は `0020000D`（StudyInstanceUID）、`00100020`（PatientID）、`00080020`（StudyDate）です。静止画でもこれらのタグがある場合は照合に使い、タスク名との矛盾を拒否します。UIDが保持されていれば、タスク名の変更後も照合できます。

一つのStudyに静止画タスクと複数の動画タスクがある場合、そのStudyのガイドを該当する全タスクへ付与します。複数の接頭辞で登録された同じStudyも同様です。プロジェクト外のタスクは検索しません。

タスク内に複数のStudy UIDが混在する場合、患者IDや日付が矛盾する場合、同じStudyについて異なる入力内容が重複する場合は、全体を失敗させます。同じ識別情報と同じ生成本文を持つ重複レコードは一つにまとめます。

該当タスクのないレコードはスキップし、件数とJSON配列中の位置をジョブのstatusに記録します。全件が未一致の場合はエラーにし、成功したように見せません。患者識別子や所見本文はstatusに出力しません。

## 生成する本文

```markdown
# 概要
- 年齢：25Y
- 性別：M
- 検査方法：CT

## 検査概要
- 検査部位：brain
- 検査履歴：History text
- 検査目的：Objective text

## 所見
所見本文

## 診断
診断本文
```

年齢、性別、検査方法は `input` の値を保持します。月齢を年齢へ換算したり、性別コードや検査方法を独自に翻訳したりしません。検査概要は `result.extracted.part`、`history`、`objective` を使用し、配列は順番を保って改行で連結します。

所見と診断は独立に、`result.*_ja`、`result.*_jp`、`result.extracted.*`、`result.*_en`、`result.*` の順で最初の空でない値を使います。日本語がない側だけ英語へ切り替えます。

null、空文字列、空配列は省略します。ただし所見と診断の見出しは残し、本文がない場合は「記載なし」とします。選択対象の内容が全て空ならエラーにします。入力の改行は保持し、MarkdownやHTMLの記号は文字として表示するためにエスケープします。患者ID、Study UID、日付、施設情報、APIの解析結果、処理時間などは生成本文に追加しません。

## 既存ガイドと再取り込み

初回は次の不可視コメントで囲んだ本文を追加します。既存ガイドがある場合、その内容の後ろに追加します。

```markdown
<!-- cvat:study-report:start -->
生成した本文
<!-- cvat:study-report:end -->
```

再取り込みでは囲まれた範囲だけを置き換えます。前後の手書き本文と既存の添付参照は保持し、同じ内容なら保存も行いません。自動生成範囲の中を手編集した場合、その変更は次の取り込みで置き換わります。手書きの追記は範囲の外へ置いてください。コメントが欠けている場合や複数ある場合は、既存本文を推測で消さずにエラーにします。

## 権限と保存

既存のプロジェクトインポート権限に加え、実行者の現在の権限で各タスクの標準 `AnnotationGuidePermission` を確認します。未作成のガイドには作成権限、既存のガイドには更新権限が必要です。キューの利用者情報がない場合や利用者が無効になっている場合も拒否します。

全対象の照合、権限、生成本文を検証してから保存します。標準DBトランザクションと行ロックを使い、保存途中に例外が発生した場合はDB変更をロールバックする構成です。このインポーター同士とPR11のインポーターはプロジェクトの行ロックで直列化します。通常のUIによる手編集との同時更新を、独自の版管理で調停する機能は追加していません。

独自DBテーブル、マイグレーション、API、依存パッケージ、サービス、Dockerfileの変更はありません。既存のバックエンドファイルへの接続は `formats/registry.py` の登録1行です。

## 制限と検証

入力はUTF-8 JSONで32 MiB、50,000レコードまでです。生成部分と既存本文を合わせたガイドは1,000,000文字までです。重複JSONキー、不正Unicode、NUL、非有限数、対応外の選択フィールド型は拒否します。入力ファイル自体はリポジトリへ追加しません。

次のコマンドで追加テストを実行します。

```sh
python -m unittest discover -s tests/python/unit -p test_task_guide_import.py -v
```

今回の実行結果は34件成功です。うちインポート接続の8件はORM、OPA、RQを模擬したテストです。別途、提供されたサンプル30件について、各Studyの静止画と動画を模した計60タスクの照合と、再取り込みでの重複防止を確認しました。

実CVAT、PostgreSQL、OPA、RQ、ブラウザーを接続した結合試験、Dockerビルド、バックアップ復元は今回未実施です。実環境では、プロジェクトの取り込み画面からJSONを送信し、Requestsの結果、タスクのInfo、画像と既存アノテーションの維持、権限不足時の非更新を確認してください。

# モデル管理の構成とAPI

[モデル管理の案内](README.md) / [モデル作成仕様](model-development.md)

このページは接続処理やモデル管理を変更する開発者向けです。画面の操作は[利用手順](usage.md)、ホストへの設定は[配備手順](deployment.md)に分けています。

## 構成要素と信頼境界

CVATの既存Nuclio接続を中継し、ONNXモデルの追加ごとにCVAT本体やNuclio関数を変更しない構成です。

| 要素 | 役割 |
|---|---|
| CVATのUIプラグイン | モデル管理へのリンクと公開モデル一覧の更新を提供します。 |
| リバースプロキシ | 同じ公開オリジンの/model-registry/を管理サーバーへ転送します。 |
| model-gateway | Nuclio関数とONNXモデルの一覧を統合し、推論を転送します。 |
| model-registry | 認証、公開一覧、登録、版管理、ログ、ワーカーの起動と停止を管理します。 |
| 推論ワーカー | 版ごとのコンテナでmodel.pyとONNXを実行し、図形またはタグを返します。 |
| 保存先 | SQLite、登録コード、重み、試験画像とログを保持します。 |

ブラウザーのセッション認証と、中継のサービス間認証は別です。ONNXモデルは中継が提供する仮想的な関数であり、Nuclio dashboardでは管理しません。公開モデルを実行者や組織ごとに非公開にする機能はありません。所有者による管理権限と推論の実行範囲を混同しないでください。

## CVATのログイン状態を使う画面と認証

MR_PUBLIC_URLはCVAT画面とスキーム、ホスト名、ポートを揃えます。プロキシは/model-registryの接頭辞を取り除いて管理サーバーへ渡します。

管理APIは要求ごとに、ブラウザーが送ったCVATのセッションCookieだけを、設定済みMR_CVAT_URLのGET /api/users/selfへ転送します。接続先はMR_CVAT_URL、HostとX-Forwarded-Protoは管理者設定のMR_PUBLIC_URLから決めます。ブラウザー指定の任意接続先や転送ヘッダーを照会先へ引き継ぎません。Cookieのパスは/を使用します。

```http
Accept: application/vnd.cvat+json
```

独自のログイン、ユーザー登録、パスワード受け付け、トークン取得、セッション発行は行いません。ログアウト、期限切れ、利用停止、削除は次の要求で確認します。既に受理した登録や中継経由の推論を取り消す処理ではありません。

有効なセッションがない場合は401、アクセス拒否は403です。CVATの400と406は連携エラーの502に変換し、本文で公開ホスト設定と応答形式の問題を区別します。到達不能や予期しない応答は503として扱い、ログイン失効とは区別します。CVAT更新時にはメディアタイプとAPIバージョンも認証テストで確認します。

公開済みモデルは認証した全メンバーへ表示し、連絡先は作者がauthor_contactに記入した値だけを公開します。非公開の登録状態、更新、削除、試験、版の切り替え、ログは所有者と管理者だけが操作できます。ボタンの非表示だけでなく管理APIで検査します。操作要求のOriginとヘッダーの検査は[セキュリティ](security.md)を参照してください。

## 新規登録と部分更新のAPI

以下の経路は管理サーバーのAPIです。ブラウザー向け公開経路には/model-registryが付きます。

| 操作 | 経路と入力 |
|---|---|
| 新規登録 | POST /api/upload。multipartのmanifest、code、weights、sampleを送ります。 |
| 既存モデルの更新 | POST /api/models/{model_id}/update。expected_revisionは必須で、変更するmanifest、code、weights、sampleだけを送ります。 |

新規登録でmodel_idやexpected_revisionを含む未知のフィールドを送ると、空欄でもHTTP 422です。旧更新要求を新規モデルとして誤って受理しません。全ファイルを差し替える更新も同じ更新経路を使い、モデルIDはフォームでなくURLに指定します。外部ZIP登録と互換用の更新経路はありません。

更新の基準には公開中の版が必要です。未公開の登録失敗は修正ファイルで新規登録し、削除済みモデルは更新できません。変更のない要求は拒否します。

manifestは部分的なJSONです。省略した項目は保持し、任意文字列への空文字はその値を消去します。polygonは子のキーごとに統合します。weightsを指定する場合は、公開中のファイル名リストと一致させます。重みの追加、削除、改名は対象外です。未指定のコード、重み、補助Pythonモジュール、試験画像を保持し、置換コードはmodel.py、ONNXは大小文字を含む既存名と一致させます。

更新は完全な候補を別に組み立て、試験推論と出力検査に成功した場合だけ公開します。内部ZIPは保存と検査の形式であり、利用者がアップロードする形式ではありません。所有権とexpected_revisionを検査し、他の更新や削除を上書きしません。検証失敗時は公開中の版を維持します。

## 中継が提供するAPI

| 経路 | 動作 |
|---|---|
| GET /api/functions | Nuclio関数とONNXモデルの一覧を統合します。 |
| GET /api/functions/{id} | 指定関数の情報を取得します。 |
| POST /api/function_invocations | x-nuclio-function-nameで指定された関数を呼び出します。 |

mr-は登録ONNXモデル専用の接頭辞です。実Nuclio関数が同じ接頭辞を使用した場合は衝突として拒否し、別の関数へ転送しません。SAMのクリック、追跡状態や追加フィールドは本文を作り直さずに転送します。

片方の接続先が停止している場合は他方の一覧を返し、X-Model-Catalog-Unavailableとログに障害を記録します。両方が停止した場合はエラーです。中継自身が停止すると両方を実行できません。CVATサーバーと自動アノテーション用ワーカーはmodel-gateway:8070へdashboard方式で接続します。仮想関数には公開ポートがないためdirect方式は使用できません。

## 出力の変換と検査

Segmentationの二値配列と旧Mask出力を共通ワーカーでポリゴンへ変換し、管理サーバーが型と座標を再検査します。Detectionは矩形、Classificationは座標のないタグです。いずれも既存detector関数形式でCVATへ公開し、CVAT側が画像番号とタスクのラベルを付けて保存します。

二値化、NMS、クラス選択、信頼度の閾値による選別はmodel.pyで行います。CVATから渡すthresholdは追加の選別に使用しません。Classificationの独自関数種別や信頼度用のCVAT属性は追加しません。出力仕様と上限は[モデル作成仕様](model-development.md)を正本とします。

## 一覧の更新と版管理

CVAT側プラグインは5秒周期と画面復帰時に一覧を確認します。同時の取得を重ねず、アカウント変更前の応答は破棄し、通信失敗だけで直前の一覧を消しません。非表示や接続切れのタブへ即時通知する方式ではありません。

モデル更新ごとに不変の版を作成し、試験成功後に基準の版との一致を確認して、1回のデータベーストランザクションで公開先を切り替えます。

```text
mr-{20桁のモデルID}-{16桁の版ID}
```

一覧には現在公開中の版だけを返しますが、過去のIDも実行可能なまま保持します。このため一括処理中の版は変わりません。更新後に新しい版を使う場合は、画面でモデルを選び直します。

モデル削除は最初に削除済みの記録と削除ログを同じDBトランザクションで確定し、新しい推論・更新を拒否します。モデルごとに受け付け済みの推論、版の切り替え、更新のコピー、登録の待機・検証を数え、全処理の終了後にワーカーを停止して全版のファイルを削除します。待機中の登録は展開前に削除状態を確認し、既に検証中の候補も公開時の確認で拒否します。版情報、登録・更新の処理記録、通常ログを削除し、最小限の削除済み記録と削除・清掃ログを残します。保存済みアノテーションは変更しません。

ワーカー停止やファイル清掃の失敗では503を返し、削除済み状態を維持します。同じ削除要求と管理サーバーの再起動で清掃を再試行します。途中で終了しても削除済み記録があるため、ファイルが残っているモデルの実行や更新は再開しません。

## ワーカーと再起動

版ごとに1個のワーカーを読み込み、既定では2版を保持します。同じ版または全ワーカーが処理中なら503を返します。この推論経路には待ち行列がありません。上限に達すると、使用中でないワーカーのうち最も長く使用されていないものを終了します。

読み込みと1回の推論はそれぞれ90秒が上限です。超過や異常終了時は該当ワーカーを終了します。公開前の登録は最大4件を受理し、最大2件を並行して検証します。

管理サーバーの再起動時は自身のワーカーを停止します。公開済みの版は保持し、未完了の登録は既に公開済みなら成功、それ以外は失敗として復元します。同一保存先を複数の管理プロセスで使用する構成はファイルロックで拒否します。cvatctl downは管理インスタンスと保存先に属するワーカーを、異常終了で残ったものも含めて停止し、コンテナだけを削除します。

## 上流更新時の確認対象

Nuclio互換API、関数メタデータ、矩形とポリゴンとタグの形式、CVATのCookieとユーザー情報API、プラグインの登録と一覧更新を確認します。管理サーバーとワーカーを同じ変更に合わせてビルドし、[検証手順](testing.md)で有効な独自拡張も確認します。

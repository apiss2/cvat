# 構成とCVATへの接続

## 構成要素の役割

この構成は、モデルの追加ごとにCVAT本体やNuclio関数を変更しないために、ONNXモデルの管理と実行を別サービスへ分離します。
CVATはNuclioとの既存の接続方式を使い、中継サービスが既存のNuclio関数と登録したONNXモデルをまとめて提供します。

| 構成要素 | 役割 |
|---|---|
| CVATのモデル管理リンク | CVATと同じホストの `/model-registry/` を開きます。 |
| リバースプロキシ | `/model-registry/` を管理サーバーへ転送し、同じホストで画面とAPIを提供します。 |
| `model-gateway` | CVATからの関数一覧、関数情報、推論要求をNuclioまたは管理サーバーへ転送します。 |
| `model-registry` | 認証、公開一覧、登録、版管理、ログ、ワーカーの起動と停止を行います。 |
| 推論ワーカー | モデルの版ごとのコンテナで `model.py` とONNXを実行し、検出枠またはポリゴンを返します。 |
| データ保存先 | SQLiteデータベース、登録コード、重み、試験画像、イベントログを保持します。 |

管理画面への経路は、ブラウザーからCVATの公開ホストを経由して管理サーバーへ接続します。
推論要求の経路は、CVATサーバーまたは自動アノテーション用ワーカーから `model-gateway` へ接続し、中継先のモデルを呼び出します。
これらの経路は認証方法も異なるため、ブラウザー用のセッションを中継サービスの認証に使いません。

ONNXモデルは中継サービスが公開する仮想的な関数です。
NuclioダッシュボードにONNXモデルは表示されず、登録と削除はモデル管理画面から行います。
既存のSAM2などはNuclio関数として引き続き実行します。

## CVATのログイン状態を使う画面と認証

管理画面の公開URLは `MR_PUBLIC_URL` に設定します。
標準の配置先は `https://CVATのホスト/model-registry/` です。
CVAT画面と管理画面のスキーム、ホスト名、ポートを揃え、同じオリジンで提供します。
同じサーバー上で動かす構成ではTraefikがこのパスを転送し、別の推論サーバーを使う構成ではCVAT側の既存プロキシに同じ経路を追加します。
プロキシは `/model-registry` の接頭辞を取り除いて管理サーバーへ渡します。

CVATのモデル管理リンクから、そのままモデル一覧を開きます。
ブラウザーが送ったCVATのセッションCookieだけを、管理サーバーから設定済みの`MR_CVAT_URL`の`GET /api/users/self`へ転送して利用者を確認します。
内部接続先は`MR_CVAT_URL`を使用し、HTTPの`Host`と`X-Forwarded-Proto`は管理者が設定した`MR_PUBLIC_URL`から作成します。
これにより、Djangoが内部サービス名の`cvat_server`を不正な公開ホストとして拒否する問題を避けます。
ブラウザーから送られた任意の接続先や転送ヘッダーは、この認証照会へ引き継ぎません。
CVATが発行するCookieの送信対象に `/model-registry/` が含まれる必要があり、CVAT標準のCookieパス `/` を使用します。
独立したログイン画面、ユーザー登録、パスワードの受け付け、CVATトークンの取得、管理画面専用のセッション発行は行いません。
有効なセッションがない場合は、同じタブでCVATへ戻る案内を表示します。
アカウントの作成とパスワードの変更はCVAT側の設定に従います。
CVAT本体のコードを変更したり、管理サーバーへ取り込んだりせず、既存のHTTP APIを利用します。

ユーザー情報の照会では、CVATのバージョン付きJSON APIで定義されたメディアタイプを指定します。現在のCVAT API契約では次のヘッダーを使用します。

```http
Accept: application/vnd.cvat+json
```

CVATを更新する場合は、接続先のユーザー情報APIと公開スキーマでこのメディアタイプとAPIバージョンの扱いを確認し、変更があれば管理サーバーと認証テストを同時に更新します。

管理APIは要求ごとにCVATのユーザー情報APIで利用者を確認します。
CVATからのログアウト、セッションの期限切れ、利用停止、ユーザー削除は、次の管理API要求で確認されます。
有効なセッションがない場合は401、CVATで利用が拒否された場合は403を返します。
CVATが照会を400または406で拒否した場合は、連携エラーとして502を返します。
502の応答本文は、400では公開ホスト設定の確認、406では要求した応答形式の不一致を示します。
通信できない場合や、それ以外の予期しない応答では503を返します。
画面は連携設定と通信のエラーをセッション失効と区別し、CVATへ戻る操作と再試行を表示します。
この確認は既に受理した登録処理や中継経由の推論を取り消すものではありません。

管理サーバーを再起動しても、CVATのセッションが有効であればログインをやり直す必要はありません。
Cookieの条件と操作時の検査は[実行権限と情報の保護](security.md)を参照してください。

## 一覧の公開範囲と所有者

公開済みのモデルは、認証した全メンバーの一覧に表示します。
他人のモデルについて返す情報は、モデルID、作者名、作成日時、公開版のID、公開版のマニフェストなど、一覧と説明に必要な内容です。
作者の連絡先はマニフェストの `author_contact` へ明示して保存した内容だけを使います。

所有者と管理者は、モデルの更新、削除、試験、過去の版への切り替え、処理状態、ログを操作できます。
公開済みでない登録や失敗した登録は、所有者と管理者だけが確認できます。
この権限は管理APIで検査するため、画面上で操作ボタンを非表示にする処理だけに依存しません。

CVATへ公開したモデルの実行範囲は、管理画面の所有者制御とは別です。
既存のNuclio呼び出しにはCVATの実行者情報を引き継がないため、公開モデルをCVATの利用者や組織ごとに非公開にする機能はありません。
CVATで該当の推論機能を利用できる利用者は、公開モデルを実行できます。

## 中継が提供するAPI

中継サービスは、CVATが使用する次のNuclio互換APIを提供します。
CVATから受け取った関数IDで転送先を選びます。

| 経路 | 動作 |
|---|---|
| `GET /api/functions` | Nuclioの関数とONNXモデルの一覧を統合します。 |
| `GET /api/functions/{id}` | 指定した関数の情報を取得します。 |
| `POST /api/function_invocations` | `x-nuclio-function-name` に対応する関数を呼び出します。 |

ONNXモデルのIDには `mr-` 接頭辞を予約します。
実際のNuclio関数が同じ接頭辞を使っている場合は衝突としてエラーにし、別の関数を実行しません。
既存SAM2などへ転送する本文は作り直さず、クリック、追跡状態、追加のフィールドをそのまま渡します。

一覧取得では片方の接続先が停止しても、もう片方の一覧を返します。
両方が停止した場合はエラーにし、停止した接続先は `X-Model-Catalog-Unavailable` ヘッダーとログへ記録します。
中継サービス自体が停止すると、CVATから両方の接続先を呼び出せなくなります。

CVAT側の呼び出し方式は `dashboard` を使います。
仮想的な関数には直接接続する公開ポートがないため、`direct` 方式では呼び出せません。
CVATサーバーと自動アノテーション用ワーカーの両方に `model-gateway:8070` を設定します。

## セグメンテーションの変換位置

モデルコードは、入力画像と同じ縦横サイズのラベル別二値配列 `(N,H,W)` を返します。
共通ワーカーが連結領域をポリゴンへ変換し、管理サーバーが形式と座標を検査してからCVATへ返します。
ポリゴンの頂点間隔と最小面積はマニフェストに保存するため、使用する版が同じなら変換設定も同じになります。

二値化はモデルコードが行います。
共通ワーカーにはモデル依存のしきい値を持たせず、CVATから届く互換用の `threshold` フィールドを結果の選別に使用しません。
出力配列とポリゴン変換の具体的な契約は[モデル作成手順](../../components/model_registry/README.md)を参照してください。

## 一覧の更新と版管理

管理サーバーは公開中の版をデータベースから都度読み出します。
公開が完了した後は、次の一覧要求から新しい版を返します。
CVATや中継サービスの設定へ個々のモデルを追加する必要はありません。

CVATのプラグインは、5秒周期と画面復帰時に関数一覧を確認します。
通信中の要求を重ねず、ログアウトやアカウント切り替え前の古い応答を破棄し、通信エラーだけで直前の一覧を空にしません。
反映には通常5秒程度と通信時間がかかり、非表示のタブや接続が切れた画面へ即時通知する機能はありません。

モデルを更新するたびに、不変の版と次の形式の関数IDを作成します。
公開前の試験が成功すると、現在の版が更新開始時の版と一致することを確認し、1回のデータベーストランザクションで公開先を切り替えます。
他の更新が先に完了していた場合は競合として扱い、先の更新を上書きしません。

```text
mr-{20桁のモデルID}-{16桁の版ID}
```

一覧には現在公開している版だけを表示し、過去の版はIDを指定すれば実行できる状態で保持します。
これにより、CVATが複数フレームを処理している途中で重みや変換設定が別の版へ切り替わることを防ぎます。
同じ理由で、古いIDを保持した画面は旧版を呼び出せるため、更新後に新しい版を使う場合はモデルを選び直します。

モデルの削除は全版を無効にします。
既に受理した1枚の推論は完了する場合がありますが、後続のフレームは失敗する可能性があります。
削除時にCVATへ保存済みのアノテーションを消す処理や、重みを物理削除する処理はありません。

## ワーカーと再起動

モデルの版ごとに1個のワーカーを読み込み、既定では2版まで保持します。
同じ版が処理中、または全てのワーカーが処理中で空きがない場合は503を返します。
この推論経路には待ち行列がないため、CVATの自動アノテーションが失敗した場合は、他の処理が終わってから再実行します。

保持できる版の数に達した場合は、処理中でないワーカーのうち最も長く使われていないものを終了します。
読み込みと1回の推論にはそれぞれ90秒の上限を設け、超過やプロセス異常時は該当ワーカーを終了します。
公開前の登録は最大4件まで受理し、その処理は最大2件を並行して進めます。

管理サーバーの再起動時は、自身の管理インスタンスに属するワーカーを停止します。
公開済みの版は保持し、未完了の登録は、公開が既に完了していれば成功、それ以外は失敗として復元します。
同じ保存先を複数の管理プロセスで共有する構成はファイルロックで拒否します。
`cvatctl down`は管理サーバーに続いて、そのインスタンスと保存先に属する推論ワーカーも停止します。
管理サーバーの異常終了で残ったワーカーも対象に含め、停止後にモデルデータを保持したままワーカーのコンテナを削除します。

## 上流CVATを更新するときの確認箇所

CVATとの接続設定は拡張の起動スクリプト、追加Compose、UIプラグインに集約します。
`CVAT_EXTENSIONS`に`model_registry`を指定すると、同じホストの管理サーバー、中継サービスと画面の拡張をCVATと同じComposeへ組み込みます。
`cvatctl build`は管理サーバーとONNX推論ワーカーのイメージもビルドし、`up`と`down`でまとめて起動と停止を行います。
接続先に別ホストを明示した場合だけ、推論ホストの`registryctl.py`で独立した管理サーバーを操作します。

上流更新時には、Nuclioの上記3経路、関数メタデータ、検出結果のポリゴン形式、CVATのセッションCookieとユーザー情報API、UIプラグインの登録と一覧更新処理を確認します。
実際に有効化した拡張も回帰確認し、ITGformatを使う環境では読み書き、SAM2を使う環境では対話操作と追跡を確認します。

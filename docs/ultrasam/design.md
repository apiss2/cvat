# UltraSAMの推論とCVATへの接続

## CVATとの接続

UltraSAMはCVAT標準のNuclio interactorとして登録します。
CVATは現在画像と正負のポイントを既存のlambda APIから関数へ渡し、返されたマスクを標準の画面操作で注釈へ反映します。
UltraSAM専用のCVAT API、UIプラグイン、データベースモデルは追加しません。

| 項目 | 値 |
|---|---|
| 拡張機能名 | `ultrasam` |
| Nuclio関数ID | `pth-ultrasam-interactor` |
| 画面の表示名 | `UltraSAM (GPU)` |
| 関数の種類 | `interactor` |
| 関数の定義 | `serverless/pytorch/camma/ultrasam/nuclio/function-gpu.yaml` |
| 入力対象 | 現在画像と、同じ画像上の正例点および負例点 |
| 出力対象 | 1個の対象の二値マスク |

画像分割は要求単位で完了し、動画の追跡セッションを作りません。
モデルは関数の初期化時に読み込み、試行推論が成功してから要求の受付を開始します。
確定した注釈はCVATの標準保存処理で保持します。
同じ画像へ点を追加する際は、ワーカーごとに直前の画像特徴を再利用します。
画像の寸法と内容のSHA-256が変わると再計算し、正負のポイントは毎回の要求に含まれるものだけを使用します。
画像特徴の切り替えから推論までをロックして、同じワーカーへ届いた要求の画像とポイントが混在しないようにします。

## 公式モデルを使用する範囲

公式UltraSAMはOpenMMLabの設定とモデル実装で推論します。
この拡張も公式の画像特徴抽出、マスク推論と重みを使用します。
公式の実行例と依存関係は[README](https://github.com/CAMMA-public/UltraSam)に記載されています。

ポイント入力にはCVAT向けの処理を追加します。
公式のプロンプト生成処理が想定する単一の正例点に対し、CVATから受け取る複数の正例点と負例点を同じ対象のプロンプトへまとめます。
画像特徴抽出やマスク推論を別モデルへ置き換えず、ポイントの符号と座標を公式モデルの入力表現へ変換します。

この拡張では、ポイントを元にした1回の推論で生成した3個の候補から、予測IoUが最大のマスクを選択します。
ユーザーが指定した正負のポイントを次の推論にも使用するため、予測した矩形やマスクをプロンプトへ置き換える自動refinementは実施しません。

単一点の比較では、公式の初回推論が返すlogitと予測IoUに対する整合を確認します。
複数の正負点を使った操作は別に確認し、CVAT画面では負例点の効果、画像座標と保存結果を確認します。

## 画像と座標の変換

RGBへ変換した画像は、公式の`FixScaleResize`で縦横比を維持して長辺1024画素へ合わせます。
続いて公式の`DetDataPreprocessor`で正規化し、右側と下側へ余白を加えます。
ポイントは縦横それぞれの実際の縮小率で座標を変換し、公式のtest pipelineと同じ`0.5`画素の補正を加えます。

出力の原寸復元は二値化前の値に対して行います。
選択した候補のlogitを余白込みの1024画素へ双線形補間し、追加した余白を除き、元画像の寸法へ再度補間してから閾値`0`で二値化します。
先に二値化したマスクを拡大すると境界の扱いが変わるため、単一点のモデル出力の比較と、原寸マスクの復元試験を分けて確認します。

## 入力と応答

要求はJSONで、画像はBase64、ポイントは元画像上の`[x, y]`で受け取ります。
正例点は1個以上必要です。
矩形だけを指定する入力や動画追跡の要求は処理しません。

| 項目 | 入力条件 |
|---|---|
| 画像 | 1フレームの画像をRGBへ変換します。画素数は16,777,216以下、要求本文は32 MiB以下です。 |
| 座標 | 数値の`[x, y]`とし、`0 <= x < width`、`0 <= y < height`を満たす必要があります。 |
| 点数 | 正例点と負例点の合計で128個までです。 |
| 矩形 | `obj_bbox`による矩形プロンプトは受け付けません。 |

```json
{
  "image": "BASE64_ENCODED_IMAGE",
  "pos_points": [[240, 160]],
  "neg_points": [[320, 190]]
}
```

応答はCVATのinteractor version 2で使うmask形式へ変換します。
画像寸法とポイントの検査に失敗した要求はエラーにし、不正なマスクを正常な結果として返しません。
画像の縮小と復元では座標の対応を維持し、元画像の範囲に収まる二値マスクを返します。

マスクは最小の外接矩形で切り出し、行方向の走査による**ランレングス**（同じ値が連続する長さ）と、両端を含む`x0, y0, x1, y1`を`points`へ格納します。
先頭の値は背景が連続する長さで、先頭画素が前景なら`0`から始めます。
次は座標`[240, 160]`の1画素だけが前景の場合の応答です。

```json
{
  "shapes": [
    {
      "type": "mask",
      "points": [0, 1, 240, 160, 240, 160],
      "attributes": []
    }
  ]
}
```

前景がない結果は`{"shapes": []}`として返し、空の注釈図形を作りません。
入力検査のエラーはHTTP 400または413、内部推論の失敗はHTTP 500とします。
関数のログにはエラーの種類を残し、画像本体とポイント列を記録しません。

## 管理コマンドとの対応

| コマンド | UltraSAMに対する処理 |
|---|---|
| `config` | 選択機能、GPUと関数イメージの参照を表示します。 |
| `doctor` | 実行環境と設定を確認します。 |
| `build` | 共通のCVATイメージを準備します。Nuclio関数は`up`または`deploy-ultrasam`でビルドします。 |
| `up` | 必要なNuclio構成を起動し、関数をビルドしてデプロイします。 |
| `up --no-build` | 検証済みの既存関数イメージを使用します。 |
| `deploy-ultrasam image` | UltraSAMの画像関数を再デプロイします。 |
| `status` | Nuclioと関数の状態を表示します。 |
| `check` | 登録、稼働状態と実イメージを確認します。 |
| `down` | dashboardと管理対象の関数を停止し、再開に必要な状態を記録します。 |

UltraSAMだけを選択した構成ではSAM2専用Redisを起動しません。
同時にSAM2を選択した構成では、各モデルを別の関数イメージで動かします。
これにより、一方の推論ライブラリの更新を他方のPython環境へ反映せずに管理できます。

## GPUとネットワーク

CUDA 11.8のNVRTC本体と開発用リンクを同じ版で導入し、`libnvrtc.so`とbuiltinsを実際に読み込んでコンパイルします。
ビルド時の検査はGPUを使用せず、実行時の検査はGPU上のcuDNN畳み込みとUltraSAMの推論まで実行します。
cuDNNを検査する子プロセスが異常終了した場合は、その終了コードまたはシグナル番号を初期化エラーへ含めます。
関数の準備完了までの待機時間は、これらの検査とモデルの読み込みを含めて300秒です。
要求受付後の処理時間の上限は120秒です。

推論先のGPUは`ULTRASAM_GPU_DEVICE`で選び、関数内の`CUDA_VISIBLE_DEVICES`へ渡します。
モデルから見える`cuda:0`は、この指定で選んだGPUです。
Nuclioのローカル実行によるGPU公開とCUDAの使用先指定は別であり、この設定だけではGPUを専有しません。

関数は既存のCVATネットワークへ接続します。
関数のHTTPポートはホストへ公開せず、CVATからNuclio dashboard経由で呼び出します。
dashboardの管理用ポートは既存の共通構成に従いループバックへ限定します。

## 更新時に確認する箇所

| 更新対象 | 必要な確認 |
|---|---|
| CVAT | 標準interactorの要求、version 2のmask応答、画面での確定と保存です。 |
| Nuclio | ビルド、GPUの公開、ネットワーク、`nuctl`との版の一致、停止と復元です。 |
| UltraSAM | 設定と重みの一致、ポイント生成処理、単一点の上流比較、正負の複数点による実推論です。 |
| PyTorchとOpenMMLab | CUDAとの対応、拡張モジュールの読み込み、モデルの初期化と実GPUでの推論です。 |

関数イメージのビルド成功と、実GPUの推論成功はそれぞれ確認します。
推論に成功しても対象画像で期待する境界を生成するとは限らないため、運用する超音波画像とポイントで受入確認を行います。

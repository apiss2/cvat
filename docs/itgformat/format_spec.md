# ITGformatの入出力規約

## 画像とアノテーションの対応

入力単位はZIPです。通常画像とアノテーションは、最後の画像拡張子を除いた相対パスで対応付けます。サブディレクトリは保持します。同じディレクトリに `a.png` と `a.jpg` がある場合は、アノテーションの対応先を一意に決められないためエラーです。

```text
hoge.png
hoge.mask.hdr
hoge.mask.re4
hoge.bb
```

| ファイルの状態 | 入力の扱い |
|---|---|
| 画像のみ | アノテーションなしとして受け入れます |
| マスク一式のみ、矩形なし | マスクを取り込みます |
| 矩形のみ、マスク一式なし | 矩形を取り込みます |
| マスク一式と矩形の両方 | 両方を取り込みます |
| HDRとRE4の片方だけが存在 | エラーです |
| 全画素ゼロのマスク、対応表あり | 正常です |
| HDRの対応表がない | 全画素ゼロでもエラーです |
| 空の矩形ファイル | 矩形なしとして受け入れます |

画像形式はPNG、JPEG、BMP、TIFF、WebP、PPM、PGM、PBMを対象にします。タスクやジョブにアノテーションを入力する場合は、CVAT側に画像があればZIP内の画像を省略できます。プロジェクトへのデータセット入力では、全項目に実画像が必要です。

## HDRの画素幅とビット対応表

HDRの先頭行は、7つの数値と `mask` です。4番目の数値 `byte_count` は、復号後の1画素を表す符号なし整数のバイト数です。画像の奥行きは1です。

```text
width height 1 byte_count spacing_x spacing_y spacing_z mask
bit_index class_name
bit_index class_name
```

本実装は、次の組み合わせを受け入れます。幅はファイルごとに読み取り、同一ZIP内で異なる画素幅を使えます。

| `byte_count` | 復号後の型 | ビット番号の範囲 | 1つのHDRに定義できるクラス数 | 画素値の範囲 |
|---:|---|---|---:|---:|
| 1 | `uint8` | 0～7 | 最大8 | 0～255 |
| 2 | `uint16` | 0～15 | 最大16 | 0～65535 |
| 4 | `uint32` | 0～31 | 最大32 | 0～4294967295 |

ビットとクラスの対応は、`0 <= bit_index < 8 * byte_count` で検証します。対応表の行数だけでは判定しません。例えば、クラスが1個でもビット31に割り当てるなら4バイトが必要です。ビット番号の重複、同一クラスへの複数ビットの割当、空の名前、範囲外の番号はエラーです。

画素値については、HDRで宣言した幅に収まることと、立っている全ビットにクラス定義があることを検証します。型変換で上位ビットを捨ててから検査する処理は行いません。ビット0も通常のクラスに使えます。背景のためにビットを予約することはなく、値0は全クラスの領域外を表します。

具体例として、幅64、高さ48でビット0と31を使うHDRは次の形です。4バイトを宣言していても、定義するクラスは2個だけで構いません。

```text
64 48 1 4 1 1 1 mask
0 region
31 vessel
```

クラス名はUTF-8で読みます。HDRではビット番号の後ろ全体を名前とするため、名前の内部に空白を含められます。名前の大小文字や表記は変更しません。寸法は正の整数、画素間隔は有限の正数を要求します。配列の形状は `(height, width)` です。

## RE4の圧縮構造

RE4では、画素値と連続長を交互に保存します。各数値の格納幅は4バイトです。HDRの `byte_count` が1、2、4のいずれでも、この圧縮構造は共通です。

```text
uint32 value_0
uint32 length_0
uint32 value_1
uint32 length_1
...
```

走査順は行優先で、x方向を先に進め、その後にy方向へ進みます。同じ値は行境界を越えてまとめます。連続長は正数、その総和は `width * height` と一致しなければなりません。値と連続長の組は8バイトで、ファイルサイズは8の倍数です。

バイト順はリトルエンディアンです。参照C++実装はネイティブのバイト順で出力するため、本実装はリトルエンディアン環境で作成したデータを対象にします。他のバイト順の推定は行いません。

対応幅の上限については、RE4の値欄が32ビットのため、32ビットを超える画素値をこの構造では保持できません。HDRで8バイトなどを宣言した入力は、実際の値が小さくても非対応として拒否します。対応幅は1、2、4バイトであり、任意のバイト数の整数を扱う実装ではありません。

## 矩形ファイルの規約

矩形は `.bb` の1行に1個を置き、7つの値を空白で区切ります。xとyは画像の画素座標です。小数を受け入れ、丸めや画像内への切り詰めは行いません。

```text
x1 y1 z1 x2 y2 z2 class_name
```

クラス欄は、空白を含まないクラス名として扱います。`7` という値も、CVATのデータベースIDやマスクのビット番号ではなく、名前が `7` のクラスを表します。矩形のクラス数にマスクのビット数制限は適用しません。

座標については、`0 <= x1 < x2 <= width` と `0 <= y1 < y2 <= height` を要求します。z座標は入力時に `(0, 0)` または `(0, 1)` を受け入れ、出力時は奥行き1の半開区間として `(0, 1)` にそろえます。

導入時は、既存の矩形データがこの解釈に一致することを確認してください。矩形の参照実装や実データは同梱されていないため、クラス欄とz座標は本連携で使用する契約として定めています。

## 出力する形状とファイルの生成条件

出力対象の形状は、次のとおりです。表現できない形状を黙って削除することはせず、出力をエラーにします。

| CVATの形状 | 出力 |
|---|---|
| マスク | クラスに割り当てたビットへ保存します |
| 多角形 | pycocotoolsで画像サイズのマスクへ変換します |
| 楕円 | CVATの `EllipsesToMasks` でマスクへ変換します |
| 回転のない矩形 | `.bb` に保存し、マスクにはしません |
| 回転矩形 | 回転を保存できないためエラーです |
| 点、折れ線、タグ、骨格など | 保存先がないためエラーです |

ファイルの生成条件は、画像ごとではなく出力対象全体で決めます。セグメンテーション形状が1個でもあれば、全画像に `.mask.hdr` と `.mask.re4` を作ります。矩形が1個でもあれば、全画像に `.bb` を作ります。形状のない画像には、全画素ゼロのマスクまたは空の矩形ファイルを作ります。該当種類の形状が全くなければ、その種類のファイルは作りません。

対象範囲は、CVATの既存抽出器が返す画像一覧です。タスク、ジョブ、プロジェクトに応じて範囲が変わります。対象内の未アノテーション画像は含め、削除画像や範囲外のフレームを独自に加えません。`outside` の形状は出力にも容量判定にも含めません。

## 出力時のクラス数と画素幅

出力では、対象全体でセグメンテーションに使われる異なるクラス名の集合を作ります。矩形だけに使うクラスと未使用クラスは含めません。この集合をUnicode順に並べ、ビット0から連続して割り当てます。

画素幅は、この集合の要素数 `N` に基づいて選びます。同じ出力の全HDRに、共通の幅と対応表を書きます。

| `N` | 出力 |
|---:|---|
| 0 | マスクを生成しません |
| 1～8 | 1バイト画素、ビット0から順に割当 |
| 9～16 | 2バイト画素、ビット0から順に割当 |
| 17～32 | 4バイト画素、ビット0から順に割当 |
| 33以上 | 共通対応表がRE4の容量に収まらないためエラー |

入力の判定は、各HDRの幅と対応表に対して行います。例えば、複数画像の対応表を合計すると40クラスあっても、各画像がそれぞれの幅に収まっていれば取り込めます。ただし、その40クラスを使った全画像を一括出力すると、共通対応表の容量を超えるためエラーです。画像ごとの容量と、共通対応表を使う出力範囲の容量を区別してください。

## 保持する情報と保持しない情報

領域については、同一クラスの複数形状を和集合にします。異なるクラスが同じ画素を占める場合は両方のビットを立て、描画順で片方を消しません。元からマスクで表された穴は保持し、入力マスクはCVATでもマスクとして保存します。

一方、同一クラス内のインスタンス区別、グループ、属性、追跡ID、描画順は保存しません。多角形の頂点列もマスクへの変換後には残りません。これらを保持するためのバックアップ形式ではありません。

また、入力時のビット番号、画素幅、物理的な画素間隔はCVATに保存しません。再出力時にはクラス集合から対応表と画素幅を決め、画素間隔をすべて1にします。例えば、ビット31に1クラスだけを置いた4バイト入力は、再出力時にビット0の1バイトマスクになります。クラス別の領域を比較し、整数画素値やHDR全体の一致を要求しないでください。

## 補助の画像一覧

出力には、画像名、画像寸法、クラス一覧、subsetを記録する `itgformat.json` を付けます。画像を含めない出力でも、マスクも矩形もない画像を一覧に残すためです。画像の拡張子も記録します。

```json
{
  "format": "ITGformat",
  "version": 1,
  "labels": ["region", "vessel"],
  "items": [
    {"id": "hoge", "subset": "default", "image": "hoge.png", "width": 64, "height": 48}
  ]
}
```

入力では画像一覧を省略できます。その場合は画像とアノテーションの名前から一覧を作り、subsetを `default` とします。画像一覧がある場合はその一覧を正とし、記録されていない画像やアノテーションはエラーです。

複数subsetの出力では、subset名のディレクトリごとに保存し、画像一覧に元の画像IDとsubsetを別々に記録します。同一subset内で画像IDが衝突する場合は、自動で名前を変えずエラーにします。

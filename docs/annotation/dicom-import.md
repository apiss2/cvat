# DICOMをプロジェクトへ取り込む

## 操作

既存の設定を保持したまま、`.env` の `CVAT_EXTENSIONS` に `dicom_import` を追加します。通常の `components/extensions/cvatctl` の更新手順でサーバーとUIを再ビルドし、起動します。`config` と `doctor` に選択が反映されます。追加サービス、GPU、DBマイグレーションはありません。

プロジェクトの Actions で **DICOM import** を開き、フォルダまたはファイルを選択するかドロップします。フォルダ内は下位フォルダまで探索し、DICOMファイル、ZIP、TAR、TAR.GZ、TGZを取り込みます。ドロップ領域の下にある必須の接頭辞欄へ、データの提供元などを示す文字列（例: `GRD`）を入力して登録します。受付後は標準の Requests で進捗を確認できます。処理完了時はDICOMプラグインが結果を通知し、一部のタスクだけが失敗した場合は警告、全タスクが失敗した場合はエラーとして件数を表示します。取り込みダイアログを閉じてもサーバーの処理と結果の監視は継続します。アカウントや組織を切り替えた場合は、以前の操作に対する通知を表示しません。ブラウザーを再読み込みした場合はプラグインの結果監視が終了し、以後はCVAT標準の通知になります。送信前に閉じた場合は準備と通信を中止します。送信中に閉じた場合、既に受け付けた処理までは取り消しません。

登録は標準のプロジェクト用データセット取り込みAPIとキューを使います。一つの入力から複数タスクを作るため、通常のタスク作成画面ではなく、プロジェクトの Actions を入口としています。専用の保存APIや認証経路は追加しません。タスク用、ジョブ用のアノテーション取り込みにこの形式を指定した場合は拒否します。

選択を外して再ビルド、再起動すると入口と取り込みが無効になります。登録済みの画像、動画、Tagは標準のデータとして残ります。DICOM用パッケージは共通サーバーイメージに含まれるため、機能の選択解除だけではパッケージを取り除きません。

## 添付コードに合わせた命名と変換

画像と動画のファイル名は次の形式です。SOPInstanceUIDはピリオドを除去した末尾8文字、InstanceNumberは4桁へのゼロ埋めです。接頭辞を除く各値はDICOMから読みます。必須値がない場合、別の識別子へ黙って置換せずエラーにします。

```text
{prefix}_{PatientID}_{SeriesNumber}_{StudyDate}_{StudyTime}_{InstanceNumber:04}_{SOP suffix}.png
{prefix}_{PatientID}_{SeriesNumber}_{StudyDate}_{StudyTime}_{InstanceNumber:04}_{SOP suffix}.mp4
```

静止画のタスク名は次の形式です。Study suffixはStudyInstanceUIDのピリオドを除いた末尾8桁です。8桁未満の場合は全桁を使います。Series単位ではなく、同じStudyの静止画を一つにまとめます。マルチフレームDICOMは、上記MP4名から拡張子を除いた名前で、一つの動画タスクにします。

```text
{prefix}_{PatientID}_{StudyDate}_{Study suffix}
```

タスク名とファイル名の `{prefix}_{PatientID}` では、PatientIDが既に `prefix` とアンダースコアで始まる場合、接頭辞を重ねて付けません。例えば接頭辞が `ABC` なら、`ABC_DEFGH` はそのまま使い、`ABCDEFGH` は `ABC_ABCDEFGH` にします。大文字と小文字は区別し、先頭以外に接頭辞が含まれるだけでは省略しません。前後の空白を除いた元の値で判定するため、ファイル名用の文字置換で生じたアンダースコアはこの判定に使いません。DicomTagのPatientIDは元の値を保存します。

DICOMタグの内容に基づくドプラ、カラー、エラストグラフィなどの除外条件は移植していません。画像でないDICOMや、対象外の通常ファイルは読み飛ばします。タスクを特定できた画像DICOMの変換失敗は、そのタスク全体の失敗として記録し、他のタスクの変換は続けます。失敗したタスクの一部の画像だけを登録することはありません。タスクの特定に必要な項目が欠けている場合や、入力アーカイブ自体が不正な場合は、取り込み全体を失敗にします。

PNGは添付の画素変換に合わせ、8ビットに収まらない整数を16ビットで保存します。負値がある場合は最小値を引きます。16ビットの範囲を超える画素や浮動小数点画像は拒否します。Window、Rescale、MONOCHROME1の反転は適用しません。DICOMの元の画素値と表示用PNGの値が常に同一という仕様ではありません。RGBの並びはPNGエンコーダーに合わせて変換します。

PALETTE COLORは未対応です。画素値が色の索引であるため、そのまま単色画像として保存せず、取り込みをエラーにします。カラーLUTの適用は行いません。

動画はMP4へ変換します。FrameTime、FrameTimeVectorの正の値の中央値、CineRate、RecommendedDisplayFrameRate、30 fpsの順にフレームレートを決めます。必要な場合は動画全体の最小値と最大値で8ビット化します。MP4は非可逆圧縮であり、元DICOMの可逆保存ではありません。フレーム数と縦横寸法を再読込で検証し、暗黙の切り詰めを防ぐため奇数寸法の動画は拒否します。MPEG動画転送構文など、同梱デコーダーで復号できないDICOMには対応しません。

HighBitがBitsStoredから期待される値と異なる場合は、補正前後の復号配列について形状、型、全画素の一致と、BitsStoredの範囲内であることを確認します。一致する場合だけ一つの画像を登録します。元DICOMのHighBitをTagに残し、補正版の別画像は生成しません。

## 重複の扱い

取り込み時にプロジェクトの既存タスク名と照合し、同名タスクは重複エラーとして登録対象から外します。完全なStudyInstanceUIDが一致する場合も、既存タスクへ追加や上書きはしません。UIDが異なる場合や確認できない場合は、その件数も結果に示します。同じ入力内で異なるStudyInstanceUIDから同名タスクが生成される場合は、その名前のタスク全体を失敗として扱い、画像を混在させません。完全なUIDはDicomTagに保存し、AnnotationGuideの照合にもその値を使います。

重複や変換エラーがあるタスクと登録可能なタスクが混在する場合は、登録可能なタスクだけを保存します。一部成功の通知には、`WARNING: DICOM:` から始まる集計を警告として表示します。全件が重複などで失敗した場合は、RequestsをFailedとして扱い、エラー通知を表示します。結果には作成数、失敗数、重複名の数などを表示し、患者IDやタスク名は記録しません。

既存タスクへの画像追加やアノテーション更新は行いません。変換後にプロジェクト行をロックして名前とUIDを再確認し、このインポーター同士の同時登録を直列化します。通常のCVATタスク作成APIには新しい一意制約を加えていないため、別経路で同名タスクを同時作成する操作までは禁止しません。

静止画は新規タスクごとに、生成したPNGのSHA-256とバイト列の一致を確認して重複を除外します。出力名の順に最初の画像を残し、その画像のDICOMタグを採用します。同じ画素でも異なるメタデータを持つ後続画像のタグは統合しません。ハッシュは取り込み中だけ保持し、DB、Tag、マニフェストへ保存しません。既存タスクの画像を読み出して再照合する処理もありません。

同じ出力名かつ同一PNGであれば重複として除外します。同じ出力名なのにPNGが異なる場合、連番を付けたり上書きしたりせず失敗にします。動画同士の入力名衝突は失敗にします。動画内の同一フレームは削除しません。

## DicomTagの保存

各静止画と動画の各フレームに、標準のTagアノテーション `DicomTag` を追加します。既知の標準タグには `PatientID`、`PixelSpacing`、`StudyInstanceUID` などのKeywordを属性名に使います。Keywordがないタグとprivate tagは `00111010` のような8桁の16進タグ番号を使います。複数のタグ番号が同じKeywordを持つ繰り返しタグは、`OverlayRows_60000010` のように番号を付けて区別します。入力型は `text` です。ファイルメタ情報とデータセット直下の単純値を対象にし、Sequence、バイナリ値、解釈できないVRは除外します。入れ子は展開しません。複数値はDICOMと同じバックスラッシュ区切りで保存します。数値もテキストとして保持します。

プロジェクトにない属性だけを追記し、既存の属性、他のラベル、既存のアノテーションは置き換えません。既存のDicomTagの属性は、今回の入力にないものも含めてすべてTextである必要があります。Text以外の属性があれば、空文字の保存によって後の出力を壊さないよう、保存前に失敗にします。文字列は4096文字までで、超過値やNULを含む値を黙って切り捨てません。CVATが採番した画像パスとフレーム番号を照合してTagを付けるため、入力順をそのままフレーム番号とみなしません。

`components/dicom_import/dicom_keywords.json` にタグ番号とKeywordの対応を保存しています。取り込みにはこの対応を使い、pydicomの辞書更新によって既存の属性名が変わらないようにしています。回帰テストは固定タグと繰り返しタグの対応をpydicomの辞書と照合するため、更新時の追加、削除、変更を検知できます。対応表を更新する場合は差分を確認します。

そのDICOMにない属性には空文字を明示します。これにより、既存ラベルの既定値が画素間隔や患者識別子として補完されることを防ぎます。既存ラベルの既定値自体は変更しません。

新規属性は `mutable=false` です。ただし、これはTrackでフレームごとに値を変えるかどうかの設定であり、編集禁止ではありません。**今回のPRには読み取り専用化やAPIによる変更禁止は含みません。** DICOMタグは標準の権限で編集でき、標準の置換インポートで削除される可能性もあります。既存データの保存方式やAPI契約を変えない取り込み機能として分離しています。

患者識別情報も指定どおりファイル名とTagへ保存します。匿名化機能ではありません。アクセス範囲と保存先は通常のCVAT運用で管理します。

## 制約と障害時の動作

ブラウザーで一つのZIPにまとめ、接頭辞を指定する小さなJSONを同梱して標準APIへ送ります。入力ファイルはCRC32計算のため1 MiBずつ読み、ZIP本体はFileのBlob参照を使います。1回の入力は合計2 GiB、50,000ファイルまでです。TUSによる途中再開は使わないため、大きな入力の転送には安定した接続が必要です。プロキシのアップロード制限も適用されます。

サーバーでは展開合計20 GiB、100,000エントリー、入れ子3段、復号後1 GiB／DICOMを上限とします。上位ディレクトリ参照、絶対パス、リンク、特殊ファイル、暗号化ZIP、同じ展開先への重複を拒否します。新規メディアの保存先はローカルストレージに限定します。

入力の読み出しは命名確認と画素変換で分け、変換済みDICOMの画素キャッシュを次の入力へ持ち越しません。キューの実行開始時と変換後に、利用者の有効状態、組織、プロジェクトの次元と標準のデータセット取り込み権限を再確認します。

DB更新は標準のプロジェクト取り込みトランザクション内で行い、各タスクの登録に保存点を設けます。タスク固有の検証エラーや登録エラーでは、そのタスクのDB更新と新規メディアを取り消し、他のタスクを続けます。権限の失効、共有ラベルの不整合、保存先の障害、結果の保存失敗など、取り込み全体に関わる例外は全体を失敗にし、新規メディアディレクトリを清掃します。プロセスの強制終了やホスト障害までファイルの原子性を保証するものではありません。標準のバックアップや保守手順は引き続き必要です。

送信結果が不明な場合は自動再送しません。Requestsを確認してから再操作します。再取り込みで既存タスク名が一致すると重複エラーになるため、同じStudyへの追加画像を後から取り込む用途には使えません。

## 実装の配置と確認

変換、アーカイブ、標準保存との接続は `components/dicom_import/`、画面は `cvat-ui/plugins/dicom-import/` です。本体への接続は形式登録とDockerfileの依存関係、ソース配置です。完了通知へ集計を渡すため、標準Request APIが完了したDICOM取り込みのメッセージを返す小さな変更を行っています。プラグインは既存の `core.requests.listen` で結果を受け取ります。Requests画面の描画は標準の実装を使います。拡張管理は小さな起動入口で `components/*/extension.json` を既存カタログへ登録し、既存の管理処理へ渡します。管理処理の本体や標準タスク作成の実装は変更しません。

```bash
PYTHONPATH=. python -m pytest -c /dev/null -q components/dicom_import/tests

tsc --strict --target es2020 --module commonjs --lib es2020,dom \
  --outDir /tmp/dicom-test-build \
  cvat-ui/plugins/dicom-import/src/ts/archive.ts \
  cvat-ui/plugins/dicom-import/src/ts/api.ts \
  cvat-ui/plugins/dicom-import/src/ts/selection.ts
DICOM_TEST_BUILD=/tmp/dicom-test-build \
  node --test cvat-ui/plugins/dicom-import/tests/*.test.cjs
```

単体テストは合成データを使用します。pydicomが導入されている環境では、合成DICOMの書き出しから復号、PNG重複除外、動画変換までを実行します。導入されていない場合、そのテストモジュールはスキップします。保存接続の試験ではORM、RQとOPAを代替実装にし、Data、Task、Jobの保存先メソッドは実モデルのソースから読み込みます。ディレクトリの清掃、タスク単位の保存点、一部失敗と全件失敗、最終status保存時の失敗、権限剥奪後の拒否、完了メッセージと結果通知、ダイアログを閉じた後の通知、アカウント変更時の通知抑止を確認します。これらの試験を、稼働中のCVATでの結合試験と区別してください。

ドラフト解除前には、Composeビルド、UI全体の型検査とブラウザー操作、実CVATへの権限別取り込み、同時取り込み、途中失敗後のDBとファイルの確認、実際の圧縮DICOM、標準バックアップの復元を確認します。

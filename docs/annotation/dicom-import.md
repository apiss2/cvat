# DICOMをプロジェクトへ取り込む

## 操作

既存の設定を保持したまま、`.env` の `CVAT_EXTENSIONS` に `dicom_import` を追加します。通常の `components/extensions/cvatctl` の更新手順でサーバーとUIを再ビルドし、起動します。`config` と `doctor` に選択が反映されます。追加サービス、GPU、DBマイグレーションはありません。

プロジェクトの Actions で **DICOM import** を開き、接頭辞（例: `GRD`）と入力を指定して登録します。フォルダ選択、DICOMファイル、ZIP、TAR、TAR.GZ、TGZに対応します。ファイルのドロップにも対応します。フォルダはフォルダ選択ボタンを使います。受付後は標準の Requests で進捗を確認し、画面を閉じてもサーバーの処理は継続します。送信前に閉じた場合は準備と通信を中止します。送信中に閉じた場合、既に受け付けた処理までは取り消しません。

登録は標準のプロジェクト用データセット取り込みAPIとキューを使います。一つの入力から複数タスクを作るため、通常のタスク作成画面ではなく、プロジェクトの Actions を入口としています。専用の保存APIや認証経路は追加しません。タスク用、ジョブ用のアノテーション取り込みにこの形式を指定した場合は拒否します。

選択を外して再ビルド、再起動すると入口と取り込みが無効になります。登録済みの画像、動画、Tagは標準のデータとして残ります。DICOM用パッケージは共通サーバーイメージに含まれるため、機能の選択解除だけではパッケージを取り除きません。

## 添付コードに合わせた命名と変換

画像と動画のファイル名は次の形式です。SOPInstanceUIDはピリオドを除去した末尾8文字、InstanceNumberは4桁へのゼロ埋めです。接頭辞を除く各値はDICOMから読みます。必須値がない場合、別の識別子へ黙って置換せずエラーにします。

```text
{prefix}_{PatientID}_{SeriesNumber}_{StudyDate}_{StudyTime}_{InstanceNumber:04}_{SOP suffix}.png
{prefix}_{PatientID}_{SeriesNumber}_{StudyDate}_{StudyTime}_{InstanceNumber:04}_{SOP suffix}.mp4
```

静止画のタスク名は次の形式です。Series単位ではなく、同じStudyの静止画を一つにまとめます。マルチフレームDICOMは、上記MP4名から拡張子を除いた名前で、一つの動画タスクにします。

```text
{prefix}_{PatientID}_{StudyDate}_{StudyInstanceUID}
```

DICOMタグの内容に基づくドプラ、カラー、エラストグラフィなどの除外条件は移植していません。画像でないDICOMや、対象外の通常ファイルは読み飛ばします。画像DICOMの変換失敗は黙って読み飛ばさず、取り込みを失敗として扱います。

PNGは添付の画素変換に合わせ、8ビットに収まらない整数を16ビットで保存します。負値がある場合は最小値を引きます。16ビットの範囲を超える画素や浮動小数点画像は拒否します。Window、Rescale、MONOCHROME1の反転は適用しません。DICOMの元の画素値と表示用PNGの値が常に同一という仕様ではありません。RGBの並びはPNGエンコーダーに合わせて変換します。

動画はMP4へ変換します。FrameTime、FrameTimeVectorの正の値の中央値、CineRate、RecommendedDisplayFrameRate、30 fpsの順にフレームレートを決めます。必要な場合は動画全体の最小値と最大値で8ビット化します。MP4は非可逆圧縮であり、元DICOMの可逆保存ではありません。フレーム数と縦横寸法を再読込で検証し、暗黙の切り詰めを防ぐため奇数寸法の動画は拒否します。MPEG動画転送構文など、同梱デコーダーで復号できないDICOMには対応しません。

HighBitがBitsStoredから期待される値と異なる場合は、補正前後の復号配列について形状、型、全画素の一致と、BitsStoredの範囲内であることを確認します。一致する場合だけ一つの画像を登録します。元DICOMのHighBitをTagに残し、補正版の別画像は生成しません。

## 重複の扱い

取り込み時にプロジェクトの既存タスク名と照合し、同名タスクは読み飛ばします。既存タスクへの画像追加やアノテーション更新は行いません。変換後にもプロジェクト行をロックして名前を再確認し、このインポーター同士の同時登録を直列化します。通常のCVATタスク作成APIには新しい一意制約を加えていないため、別経路で同名タスクを同時作成する操作までは禁止しません。

静止画は新規タスクごとに、生成したPNGのSHA-256とバイト列の一致を確認して重複を除外します。出力名の順に最初の画像を残し、その画像のDICOMタグを採用します。同じ画素でも異なるメタデータを持つ後続画像のタグは統合しません。ハッシュは取り込み中だけ保持し、DB、Tag、マニフェストへ保存しません。既存タスクの画像を読み出して再照合する処理もありません。

同じ出力名かつ同一PNGであれば重複として除外します。同じ出力名なのにPNGが異なる場合、連番を付けたり上書きしたりせず失敗にします。動画同士の入力名衝突は失敗にします。動画内の同一フレームは削除しません。

## DicomTagの保存

各静止画と動画の各フレームに、標準のTagアノテーション `DicomTag` を追加します。属性名は `00100020` のような8桁のタグ番号、入力型は `text` です。ファイルメタ情報とデータセット直下の単純値を対象にし、Sequence、バイナリ値、解釈できないVRは除外します。入れ子は展開しません。複数値はDICOMと同じバックスラッシュ区切りで保存します。数値もテキストとして保持します。

プロジェクトにない属性だけを追記し、既存の属性、他のラベル、既存のアノテーションは置き換えません。既存の同名属性がTextでない場合は失敗にします。文字列は4096文字までで、超過値やNULを含む値を黙って切り捨てません。CVATが採番した画像パスとフレーム番号を照合してTagを付けるため、入力順をそのままフレーム番号とみなしません。

新規属性は `mutable=false` です。ただし、これはTrackでフレームごとに値を変えるかどうかの設定であり、編集禁止ではありません。**今回のPRには読み取り専用化やAPIによる変更禁止は含みません。** DICOMタグは標準の権限で編集でき、標準の置換インポートで削除される可能性もあります。既存データの保存方式やAPI契約を変えない取り込み機能として分離しています。

患者識別情報も指定どおりファイル名とTagへ保存します。匿名化機能ではありません。アクセス範囲と保存先は通常のCVAT運用で管理します。

## 制約と障害時の動作

ブラウザーで一つのZIPにまとめ、接頭辞を指定する小さなJSONを同梱して標準APIへ送ります。入力ファイルはCRC32計算のため1 MiBずつ読み、ZIP本体はFileのBlob参照を使います。1回の入力は合計2 GiB、50,000ファイルまでです。TUSによる途中再開は使わないため、大きな入力の転送には安定した接続が必要です。プロキシのアップロード制限も適用されます。

サーバーでは展開合計20 GiB、100,000エントリー、入れ子3段、復号後1 GiB／DICOMを上限とします。上位ディレクトリ参照、絶対パス、リンク、特殊ファイル、暗号化ZIP、同じ展開先への重複を拒否します。新規メディアの保存先はローカルストレージに限定します。

DB更新は標準のプロジェクト取り込みトランザクション内で行います。通常の例外では、その処理が新規作成したメディアディレクトリだけを清掃します。プロセスの強制終了やホスト障害までファイルの原子性を保証するものではありません。標準のバックアップや保守手順は引き続き必要です。

送信結果が不明な場合は自動再送しません。Requestsを確認してから再操作します。再取り込みで既存タスク名が一致するとスキップされるため、同じStudyへの追加画像を後から取り込む用途には使えません。

## 実装の配置と確認

変換、アーカイブ、標準保存との接続は `components/dicom_import/`、画面は `cvat-ui/plugins/dicom-import/` です。本体への接続は形式登録1行とDockerfileの依存関係、ソース配置3行です。拡張管理は小さな起動入口で `components/*/extension.json` を既存カタログへ登録し、既存の管理処理へ渡します。管理処理の本体や標準タスク作成の実装は変更しません。

```bash
PYTHONPATH=. python -m pytest -c /dev/null -q components/dicom_import/tests

tsc --strict --target es2020 --module commonjs --lib es2020,dom \
  --outDir /tmp/dicom-test-build \
  cvat-ui/plugins/dicom-import/src/ts/archive.ts \
  cvat-ui/plugins/dicom-import/src/ts/api.ts
DICOM_TEST_BUILD=/tmp/dicom-test-build \
  node --test cvat-ui/plugins/dicom-import/tests/import.test.cjs
```

単体テストは合成データを使用します。pydicomが導入されている環境では、合成DICOMの書き出しから復号、PNG重複除外、動画変換までを実行します。導入されていない場合、そのテストモジュールはスキップします。HTTP、Dataset、管理カタログの代替実装を使う試験を、稼働中のCVATでの結合試験と区別してください。

ドラフト解除前には、Composeビルド、UI全体の型検査とブラウザー操作、実CVATへの権限別取り込み、同時取り込み、途中失敗後のDBとファイルの確認、実際の圧縮DICOM、標準バックアップの復元を確認します。

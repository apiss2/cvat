# 画像のspacingに基づく物理長の表示

[アノテーション操作](README.md) / [拡張機能の管理](../extensions/management.md)

画像の**spacing**は、横方向と縦方向で1画素に対応する長さです。
この拡張は、タスクまたは画像に登録した「spacing」を使い、polylineの各線分を合計した長さをmmで表示します。
「spacing」がない画像ではpxを表示します。

## 画面で設定する

1. タスクのActions、またはアノテーション画面のMenuから「物理長」を開きます。
2. 全画像で同じ「spacing」を使う場合は「タスク共通」を有効にし、XとYを `mm/px` で入力します。
3. 一部の画像だけ異なる場合は「フレーム」で対象番号を選び、「個別」のXとYを入力します。「タスク共通」は共通値の使用、「px」はその画像での物理長表示の解除です。
4. 「保存」で確定します。フレーム番号を切り替えても、入力途中の変更は保持されます。

保存後は、作成済みのpolylineを選択するかポインターを重ねると、通常の図形ラベルと一緒に長さが表示されます。
既存の「Show all text」を有効にすると、全図形の文字表示に従って長さも表示します。
頂点編集やUndoによって確定した形状にも追従します。
描画途中の線分に対するプレビューはありません。

設定画面の「再読込」はサーバーの保存値を取得します。
他の操作による更新と競合した場合は入力を残してエラーを表示し、自動で上書きしません。
「再読込」で最新値を確認してから編集し直してください。
未保存の変更がある状態で閉じる場合も、破棄するか確認します。

タスク全体へのアクセスがなく、ジョブだけを閲覧できる担当者には、現在のフレームの設定を表示します。この場合は設定変更、フレーム番号変更、JSON入出力を無効にします。設定の保存には、既存のタスクメタデータ更新権限が必要です。

## JSONで複数画像の設定を渡す

「JSON読込」で設定をまとめて読み込み、画面で確認してから「保存」します。「JSON出力」は表示中の設定を出力するため、未保存の変更も含みます。JSONの読込と出力だけでは、サーバーの設定を更新しません。ファイル上限は1 MiBです。

次は、タスク共通値をX方向0.3 mm/px、Y方向0.4 mm/pxとし、フレーム1だけ別の値、フレーム2だけpx表示にする例です。

```json
{
  "version": 1,
  "default": { "x": 0.3, "y": 0.4, "unit": "mm" },
  "frames": {
    "1": { "x": 0.5, "y": 0.6, "unit": "mm" },
    "2": null
  }
}
```

| 項目 | 意味 |
| --- | --- |
| `version` | 設定形式の版です。現在は `1` です。 |
| `default` | タスク共通の「spacing」です。`null` は共通値なしを意味します。 |
| `frames` | タスク内のフレーム番号を文字列のキーとして指定する個別設定です。省略した番号は共通値を使います。 |
| `frames[番号] = null` | その画像をpx表示にします。共通値には戻りません。 |
| `x`、`y` | アップロードした画像の横方向と縦方向の `mm/px` です。どちらも0より大きい有限の数値を指定します。 |
| `unit` | 現在は `mm` のみです。 |

フレーム番号は、タスク内の画像順に0から始まる番号です。
ジョブごとに0へ戻さず、元動画のフレーム番号やファイル名も使用しません。
取り込み開始位置や間引きを指定した動画でも、取り込み後のタスク内の番号を使います。
タスクの画像数以上の番号は受け付けません。

設定の読込と保存は全体の置き換えです。追加したい画像だけのJSONを読み込むと、以前の個別設定は引き継ぎません。既存値を残す場合は「JSON出力」で取得した設定を編集して読み込みます。

## 長さの計算と画像変換

計算には、アノテーションが保持する画像座標を使用します。各線分のX方向とY方向の差に、それぞれの「spacing」を掛けてから長さを求め、全線分を合計します。横と縦で「spacing」が異なる画像にも対応します。

```text
長さ [mm] = Σ hypot((x[i+1] - x[i]) × spacing.x,
                   (y[i+1] - y[i]) × spacing.y)
```

例えば、座標が `(0, 0) → (10, 0) → (10, 10)` のpolylineに、X方向0.3 mm/px、Y方向0.4 mm/pxを指定すると、長さは `3 + 4 = 7 mm` です。
始点と終点だけを結んだ長さではなく、折れ線に沿った長さです。

DICOMの `PixelSpacing` は `[row, column]`、つまり `[y, x]` の順です。
値を転記するときは、第2値をX、第1値をYへ指定します。
単位と順序は[DICOMのPixel Spacing仕様](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_10.7.html)を参照してください。
この拡張はDICOMやITGformatから値を自動抽出しません。

アップロード前に画像を拡大縮小した場合は、変換後の画素に対応する「spacing」を指定します。
例えば横方向の画素数を半分にした画像では、X方向の値は元の2倍です。
画像の切り抜きだけで画素数の倍率が変わらなければ「spacing」は同じです。
90度回転して軸を入れ替えた場合は、XとYの値も入れ替えます。
CVAT画面上の拡大縮小、移動、表示回転では測定値は変わりません。

## 保存とバックアップ

設定はタスクに紐づく専用のDBテーブルへ保存します。アノテーションの座標は引き続きピクセル単位です。計算した長さをラベル属性へ追記したり、アノテーションの数値をmmへ書き換えたりはしません。

CVAT標準のタスクバックアップには `physical_measurements.json` を追加し、復元時に設定を戻します。
プロジェクトバックアップでも、各タスクの保存領域に同じファイルを含めます。
この拡張で保存した設定がないタスクには追加せず、ファイルを含まない従来のバックアップも復元できます。

通常のアノテーション出力とデータセット出力には、この設定と計算した長さを追加しません。
画像やアノテーションを別の処理へ渡す場合は、設定画面の「JSON出力」を別途保存してください。
フレームを抜き出した出力先で再利用する場合は、出力先の画像順に合わせて個別設定の番号を付け直します。

## 有効化と無効化

既存環境では、[共通の更新手順](../extensions/update.md)に従って停止とバックアップを済ませ、`.env` の `CVAT_EXTENSIONS` に `physical_measurements` を追加します。
既存機能の選択は保持してください。
次はこの機能だけを選ぶ最小例です。

```dotenv
CVAT_EXTENSIONS=physical_measurements
```

`cvatctl` が `plugins/physical-measurements` をUIのビルドへ追加します。
初回導入ではサーバーとUIを同じソースからビルドし、起動時のDB移行を確認します。
既存のDBとサーバーを使用し、追加サービス、GPU、Nuclioは要求しません。

```sh
bash components/extensions/cvatctl config
bash components/extensions/cvatctl doctor
bash components/extensions/cvatctl build
bash components/extensions/cvatctl up
docker exec cvat_server python manage.py migrate --check
bash components/extensions/cvatctl check
```

無効化する場合は、同じ管理手順で停止し、拡張名を外してUIを再ビルドします。
再配備後にブラウザーを再読み込みすると、メニューと長さ表示が消えます。
設定とAPIはサーバーに残り、再度有効にすると保存済みの設定を使います。
設定の選択だけでDBテーブルを削除したり、DB移行を巻き戻したりはしません。

## 対応範囲

対象は2D画像と動画のpolylineです。画像ごとに一定で、互いに直交するX方向とY方向の「spacing」を前提とします。3D、音声、画像未設定のタスク、GT-poolには対応しません。

超音波の領域ごとの校正、深さによって変わる倍率、扇形の座標変換、画像からの3D距離の推定は扱いません。
超音波画像の一部だけに校正値がある場合、その値を画像全体の共通値として登録しないでください。
DICOMの全タグやITGformat内の値を、画像との対応を確認せず自動転用する処理もありません。

この版はpolylineの長さ表示に限定します。矩形の辺長、polygonの周長と面積、物理単位によるアノテーションのエクスポートは対象外です。

## 実装の分離

計算、設定画面、表示の接続は `cvat-ui/plugins/physical-measurements/` に置き、保存、検証、API、
バックアップ処理は `components/physical_measurements/` に置いています。
バックエンドのアプリ登録、URL登録、Dockerへの同梱、既存バックアップへの呼び出しだけを共通部分へ追加します。

キャンバスには、既存の図形ラベルへ文字列を渡す任意の `shapeText` フックを追加します。
既存の文字位置と表示条件を再利用できるため、DOMの監視や実行時のメソッド差し替えは必要ありません。
プラグインがフックを指定しないときは、既存の図形表示を使用します。

## APIから設定する

APIは既存の認証とタスクまたはジョブの権限確認を使用します。組織を使用する場合は、通常のCVAT APIと同様に対象組織を指定します。

```text
GET /api/physical-measurements/tasks/{id}
PUT /api/physical-measurements/tasks/{id}
GET /api/physical-measurements/jobs/{id}
```

GETは、設定の `version`、`default`、`frames` に加え、`revision`、`frame_count`、`supported`、`unavailable_reason` を返します。
設定がないタスクの `revision` は `0` です。
ジョブのGETは、そのジョブに属するフレームの個別設定だけを返し、タスク共通値とタスク内の番号を保持します。
ジョブのAPIからは更新できません。

PUTは、設定全体と直前のGETで取得した `revision` を `expected_revision` に指定します。次は初回保存の例です。

```json
{
  "version": 1,
  "default": { "x": 0.3, "y": 0.4, "unit": "mm" },
  "frames": {},
  "expected_revision": 0
}
```

保存成功時は、増加した `revision` を含む新しいGET相当の応答を返します。
他の操作が先に更新していた場合はHTTP 409を返し、保存済みの設定を維持します。
入力のキー違い、無効な値、範囲外のフレーム番号、非対応タスクはHTTP 400です。
GET応答の全フィールドをそのままPUTへ渡さず、上記の4項目だけを送信します。

## 検証する

リポジトリの依存関係を用意した環境で、次を実行します。Pythonの試験にはpytest、Django、Django REST frameworkが必要です。

```sh
python3 -m pytest -q components/physical_measurements/tests \
  components/extensions/tests/test_client_plugins.py \
  components/extensions/tests/test_cvatctl.py
node --test cvat-ui/plugins/physical-measurements/tests/*.test.cjs
yarn run type-check
CLIENT_PLUGINS=plugins/physical-measurements yarn run build:cvat-ui
```

Pythonの試験は、入力検証、DBへの保存、更新競合、ジョブ範囲の制限、バックアップの往復、既存の権限確認への委譲を確認します。
DBを使う試験ではSQLiteと最小限のタスクモデルを使用し、CVAT全体のPostgreSQL、OPA、Redisを起動しません。
Nodeの試験は、長さの計算、設定の解決、API、非同期応答の入れ替わり、表示対象の切り替えを確認します。

レビュー環境では、X方向0.3 mm/px、Y方向0.4 mm/pxの画像に前述の折れ線を作り、7 mmとなることを確認します。
続けて、頂点編集、Undo、フレーム別の値、明示的なpx指定、画面の拡大縮小と回転、再読み込みを確認します。
既存のタスクバックアップとプロジェクトバックアップを復元し、設定が保持されることも確認対象です。

権限と運用の確認では、タスク編集者とジョブ担当者を分けて設定画面を開き、閲覧範囲と保存権限を確認します。
同じ設定を2画面で編集し、後から保存した古い設定が409になることを確認します。
有効化と無効化では、メニューと表示が切り替わり、保存済みの設定が消えないことを確認します。
実配備とこれらの受入確認は、自動試験や `cvatctl check` の成功とは分けて記録してください。

# 選択した画像への自動アノテーション

[アノテーション操作](README.md) / [モデル管理](../model-registry/README.md)

タスクまたはプロジェクトで、保存済みタグの条件に合う画像を選び、Segmentation、Detection、Classificationのモデルを実行します。現在の画面にダイアログを開き、新しいブラウザータブは作りません。

## 有効化

既存の.envのCVAT_CLIENT_PLUGINSへplugins/selective-aiを追加し、UIを再ビルドします。既存値を保持し、複数のパスはコロンで区切ります。

```dotenv
CVAT_CLIENT_PLUGINS=plugins/frame-navigation-filter:plugins/selective-ai
```

この例は二つの独立したプラグインを併用する設定です。選択実行だけならplugins/selective-aiのみを追加します。[共通導入](../extensions/installation.md)のビルドと起動手順を使い、直接UIを開発する場合はCLIENT_PLUGINSを使用します。

## 対象画像を選ぶ

編集済みのアノテーションを保存し、対象タスクまたはプロジェクトの操作メニューから「タグ条件で自動アノテーション」を開きます。
タスクではそのタスク、プロジェクトではその中の読み取り可能な全タスクが対象です。一覧が複数ページでも取得します。複数のタスクやプロジェクトを同時選択した状態での実行は対象外です。

選択タグのいずれか、全て、どれも付いていない画像、またはタグが一つもない画像を選べます。「タグなし」は「図形なし」ではなく、マスクだけがある画像も含みます。動画の各フレームも画像として選びます。削除済みフレームは除外します。

「対象画像を一覧表示」で対象一覧を確認し、画像ごとのチェックを変更します。一覧の表示までは推論も書き込みも行いません。フレーム番号はCVAT内で0から始まるタスク相対番号で、元動画の開始位置や間引き間隔を加えた番号ではありません。
プロジェクトに未初期化または対応外のタスクがある場合は、黙って除外せず対象一覧の取得を失敗させます。

## モデルとラベルを設定する

登録済みのモデルを選び、標準のLabelsMapperで出力ラベル、属性、Skeletonの各点を対応付けます。異なる名前の属性や点も指定できます。対応付けないラベルは保存しません。少なくとも一つの出力ラベルを対応付けてください。
Interactor、Tracker、ReIDは対象外です。必要ならマスクからポリゴンへの変換を指定できます。登録ONNXモデルのSegmentation出力が既にポリゴンの場合は追加変換は不要です。

通常のNuclio関数には信頼度の閾値を渡します。独自のモデル管理から登録したONNXモデルでは、この画面から信頼度の閾値を変更できません。選別はmodel.pyの実装に従います。
出力ラベルと型の対応は実行前に再検査します。anyとskeletonの対応は両方向とも認めません。

## 実行、保存、中止

「選択した画像に実行」を押すと、画像ごとに推論し、結果をサーバーへ追記します。既存のアノテーションを置き換えたり削除したりしません。出力がない画像には書き込みません。
完了までタブを開いたままにし、対象タスクの編集と別の自動処理を避けてください。

各タスクの処理開始時に所属、画像数、保存済みタグ、削除フレームを確認します。選んだ画像が条件から外れた場合は除外しますが、新しく条件に合った画像や新しいタスクは勝手に追加しません。タスクの処理開始後にタグを編集しても、そのタスクの対象条件には追従しません。

中止すると実行中の通信の終了を待ち、次の要求を送りません。推論中に中止した場合は保存前の結果を破棄しますが、保存中の通信は既に確定している可能性があります。保存済みの結果は残ります。
タブの終了、再読み込み、セッションの失効後の自動再開はありません。通常の自動アノテーションの永続的なサーバーキューとは異なる方式です。

最初のエラーで停止し、自動再試行しません。保存のタイムアウトや通信エラーでは、サーバーが保存していて応答だけが失われた可能性があります。対象フレームを確認してから再実行してください。追記は冪等ではなく、再実行によって図形やタグが重複する場合があります。
実行結果のJSONには選択した画像、ラベル対応、画像ごとの保存済み、出力なし、除外、失敗の結果を記録します。選択一覧と照合して未処理の画像を確認します。保存状態が不明な失敗を成功として扱わないでください。

## 実装と制約

cvat-ui/plugins/selective-ai/の範囲で、projectActions.itemsとtaskActions.itemsを使います。標準の実行画面、サーバー、データベースを変更しません。
mapper.tsxは既存のLabelsMapperとそのスタイルを再利用します。入力配列をモデル単位で保持し、進捗更新で選択を初期化しません。実行中は対応付けの操作を隠しますが、状態は保持します。

既存の認証済みAxiosを使用し、利用者と組織を固定します。変更後は新しい要求と保存を止めますが、既に送信した要求を巻き戻すことはできません。認証情報を要求、保存、結果ファイルへ記録する処理はありません。

```text
GET   /api/tasks?project_id=...&page=...&page_size=100
GET   /api/labels?task_id=...
GET   /api/labels?project_id=...
GET   /api/tasks/{id}
GET   /api/tasks/{id}/data/meta
GET   /api/tasks/{id}/annotations
GET   /api/lambda/requests
POST  /api/lambda/functions/{model_id}
PATCH /api/tasks/{id}/annotations?action=create
```

推論応答のフレーム番号、ラベルID、既存IDの不在、tracksの不在を確認します。マスクRLE、タグ、属性、Skeletonの変換は既存サーバーに任せ、ブラウザーで再実装しません。cleanup、PUT、DELETEは使いません。
ページ数の不一致、途中までしか取得できない一覧、削除された選択ラベルはエラーにします。ページごとの要求前後にも中止判定を行います。
ONNXモデルの識別には既存の予約済みmr-関数IDを使用し、表示名やファイル名から推測しません。そのモデルでは無効なthresholdを要求と実行結果から省略します。

タスク開始前に通常の自動アノテーションが実行中か確認しますが、分散ロックではありません。別ブラウザーや別利用者の同時開始を完全には防げず、既存ジョブを取り消しません。一つのタブに開けるダイアログは一つです。
対象計画は候補画像数に比例してメモリーを使用し、推論と保存は画像ごとに通信します。タグ取得時にはタスクのアノテーション全体を受信しますが、計画にマスクや画像データを保持しません。大規模な無人処理の永続ジョブは提供していません。

## 検証

```bash
node --test cvat-ui/plugins/selective-ai/tests/*.test.cjs
npx tsc --noEmit --strict --target ES2020 --lib ES2020,DOM   cvat-ui/plugins/selective-ai/src/ts/engine.ts   cvat-ui/plugins/selective-ai/src/ts/api.ts
```

単体試験は条件の組合せ、100件を超えるタスク一覧、番号、未選択フレームへの書き込み防止、出力検査、中止、保存結果不明、認証の切り替え、メニュー、属性と点の対応、閾値の送信有無を代替応答で確認します。
Mapperの試験はReactとLabelsMapperの代替実装を使用します。単独の型検査も実行処理とHTTP処理が対象で、CVAT全体の型検査ではありません。

受入確認には専用タスクを使用し、各条件、タグとマスクの混在、画像の選択解除、Classification、間引き、削除フレーム、複数ページ、権限拒否、中止、保存エラー、利用者と組織の変更を確認します。標準の自動アノテーションが変わらないこと、既存図形が残ること、異なる名前の属性と点を対応付けられることも確認してください。

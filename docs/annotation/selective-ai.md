# 画像を選んで自動アノテーションする

[アノテーション操作](README.md) / [モデル管理](../model-registry/README.md)

タスクまたはプロジェクトから対象画像を選び、領域分割、物体検出、分類のモデルを実行する機能です。Task、Job、保存済みアノテーションのフィルターで候補を絞り、画像一覧で対象を調整できます。

画面の「条件を指定して自動アノテーション」から操作します。結果はサーバーへ順次追記されるため、実行前に対象画像と保存先ラベルを確認してください。

## 対象画像を選ぶ

編集済みのアノテーションを保存し、対象タスクまたはプロジェクトの操作メニューから「条件を指定して自動アノテーション」を開きます。
タスクではそのタスク、プロジェクトではその中の読み取り可能な全タスクが対象です。一覧が複数ページでも取得します。複数のタスクやプロジェクトを同時選択した状態での実行は対象外です。

Task、Job、画像の各欄を開き、CVATと同じ条件ビルダーで指定します。初期状態は全条件なしです。指定済みの欄には青い印、入力途中の欄には警告色の印が付きます。TaskとJobは標準の一覧フィルターの全項目と比較方法を使用し、画像は条件に合うアノテーションがあるフレームを選びます。三つの範囲はANDで組み合わせます。画像条件を指定しない場合、アノテーションの有無を問いません。Job条件を指定した場合だけ通常のAnnotation Jobの範囲に限定し、Ground TruthやReplicaはJob Typeで指定しても対象に追加されません。Job条件がない場合はタスクの全フレームが対象です。重複するフレームは一度だけ選び、削除済みフレームは除外します。
画像条件のAND、OR、NOTはアノテーション単位で評価されます。例えばLabelがAではないという条件は、Aが存在しない画像を意味しません。

「対象画像を一覧表示」で対象一覧を確認し、画像ごとのチェックを変更します。一覧の表示までは推論も書き込みも行いません。フレーム番号はCVAT内で0から始まるタスク相対番号で、元動画の開始位置や間引き間隔を加えた番号ではありません。
画像が未登録の空タスクは候補に含めません。画像が存在する対応外のタスクは対象一覧の取得を失敗させます。

## モデルとラベルを設定する

登録済みのモデルを選び、標準のLabelsMapperで出力ラベル、属性、Skeletonの各点を対応付けます。異なる名前の属性や点も指定できます。対応付けないラベルは保存しません。少なくとも一つの出力ラベルを対応付けてください。
Interactor、Tracker、ReIDは対象外です。マスクからポリゴンへの変換は既定で有効です。登録ONNXモデルのSegmentation出力が既にポリゴンの場合は追加変換は不要です。

通常のNuclio関数には信頼度の閾値を渡します。独自のモデル管理から登録したONNXモデルでは、この画面から信頼度の閾値を変更できません。選別はmodel.pyの実装に従います。
出力ラベルと型の対応は実行前に再検査します。anyとskeletonの対応は両方向とも認めません。

## 実行、保存、中止

「選択した画像に実行」を押すと、画像ごとに推論し、結果をサーバーへ追記します。既存のアノテーションを置き換えたり削除したりしません。出力がない画像には書き込みません。
完了までタブを開いたままにし、対象タスクの編集と別の自動処理を避けてください。

各タスクの処理開始時に所属、画像数、TaskとJobの条件、保存済みアノテーション、削除フレームを確認します。選んだ画像が条件から外れた場合は除外しますが、新しく条件に合った画像や新しいタスクは勝手に追加しません。タスクの処理開始後の編集には、そのタスクの対象条件は追従しません。結果の保存は従来どおりTaskのアノテーション追記APIを使用し、Job条件は画像の選択にのみ適用します。

中止すると実行中の通信の終了を待ち、次の要求を送りません。推論中に中止した場合は保存前の結果を破棄しますが、保存中の通信は既に確定している可能性があります。保存済みの結果は残ります。
タブの終了、再読み込み、セッションの失効後の自動再開はありません。通常の自動アノテーションの永続的なサーバーキューとは異なる方式です。

最初のエラーで停止し、自動再試行しません。保存のタイムアウトや通信エラーでは、サーバーが保存していて応答だけが失われた可能性があります。対象フレームを確認してから再実行してください。追記は冪等ではなく、再実行によって図形やタグが重複する場合があります。
実行結果のJSONには選択した画像、ラベル対応、画像ごとの保存済み、出力なし、除外、失敗の結果を記録します。選択一覧と照合して未処理の画像を確認します。保存状態が不明な失敗を成功として扱わないでください。

## 管理者向けの設定

既存の.envのCVAT_EXTENSIONSへselective_aiを追加します。登録ONNXモデルを使う場合はmodel_registryも選び、既存の機能名を保持してください。

```dotenv
CVAT_EXTENSIONS=model_registry,frame_navigation_filter,selective_ai
```

この例ではモデル管理とフレーム移動用フィルターを併用します。CVAT標準の推論関数を動かすサービス「Nuclio」に配備済みのモデルを使う場合は、selective_aiだけでも選択実行を利用できます。cvatctlは推論APIに必要なNuclio構成を追加しますが、モデルやGPUを自動配備しません。

保存と停止、設定変更、再ビルドと起動は[共通管理の手順](../extensions/management.md)に従ってください。無効化するときもselective_aiを選択から外して再ビルドします。直接UIを開発する場合だけCLIENT_PLUGINSへplugins/selective-aiを指定します。

## 開発者向けの実装と制約

cvat-ui/plugins/selective-ai/と共通フィルター定義の範囲で、projectActions.itemsとtaskActions.itemsを使います。標準の実行画面、サーバー、データベースを変更しません。配備対象の選択は共通のcomponents/extensions/manage.pyで管理します。
filter-editor.tsxは標準のTaskとJob一覧のフィールド定義、cvat-ui/plugins/shared/annotation-filter-config.tsの共通画像フィールド定義を再利用します。条件付きエクスポートもこの共通定義を使用し、互いのプラグイン内部には依存しません。画像検索はCVAT本体のTask.annotations.searchで行い、Job条件がある場合はJob一覧の範囲と交差させます。通常の連続したJob範囲とフレーム数の不一致は、範囲外の画像へ実行しないためエラーにします。filtered_exportの有効化は不要です。

mapper.tsxは既存のLabelsMapperとそのスタイルを再利用します。入力配列をモデル単位で保持し、進捗更新で選択を初期化しません。実行中は対応付けの操作を隠しますが、状態は保持します。

既存の認証済みAxiosを使用し、利用者と組織を固定します。変更後は新しい要求と保存を止めますが、既に送信した要求を巻き戻すことはできません。認証情報を要求、保存、結果ファイルへ記録する処理はありません。

```text
GET   /api/tasks?project_id=...&filter=...&page=...&page_size=100
GET   /api/tasks?filter=...&page=...&page_size=100
GET   /api/jobs?task_id=...&type=annotation&filter=...&page=...&page_size=100  (Job条件を指定した場合のみ)
GET   /api/labels?task_id=...
GET   /api/labels?project_id=...
GET   /api/tasks/{id}
GET   /api/tasks/{id}/data/meta
GET   /api/tasks/{id}/annotations  (画像条件を指定した場合のみ、CVAT本体経由)
GET   /api/lambda/requests
POST  /api/lambda/functions/{model_id}
PATCH /api/tasks/{id}/annotations?action=create
```

推論応答のフレーム番号、ラベルID、既存IDの不在、tracksの不在を確認します。マスクRLE、タグ、属性、Skeletonの変換は既存サーバーに任せ、ブラウザーで再実装しません。cleanup、PUT、DELETEは使いません。
ページ数の不一致、途中までしか取得できない一覧、実行時に削除された出力対応ラベルはエラーにします。ページごとの要求前後にも中止判定を行います。
ONNXモデルの識別には既存の予約済みmr-関数IDを使用し、表示名やファイル名から推測しません。そのモデルでは無効なthresholdを要求と実行結果から省略します。

タスク開始前に通常の自動アノテーションが実行中か確認しますが、分散ロックではありません。別ブラウザーや別利用者の同時開始を完全には防げず、既存ジョブを取り消しません。一つのタブに開けるダイアログは一つです。
対象計画は候補画像数に比例してメモリーを使用し、推論と保存は画像ごとに通信します。画像条件を指定した場合にCVAT本体がタスクのアノテーションを読み込みます。計画にマスクや画像データを保持しません。大規模な無人処理の永続ジョブは提供していません。

## 検証

```bash
node --test cvat-ui/plugins/selective-ai/tests/*.test.cjs
npx tsc --noEmit --skipLibCheck --strict --target ES2020 --lib ES2020,DOM   cvat-ui/plugins/selective-ai/src/ts/engine.ts   cvat-ui/plugins/selective-ai/src/ts/api.ts   cvat-ui/plugins/selective-ai/src/ts/selection.ts
```

単体試験は三範囲の組合せ、条件なし、途中の条件変更、フレーム範囲の結合と検索範囲、100件を超えるタスク一覧、番号、未選択フレームへの書き込み防止、出力検査、中止、保存結果不明、認証の切り替え、メニュー、属性と点の対応、閾値の送信有無を代替応答で確認します。
Mapperの試験はReactとLabelsMapperの代替実装を使用します。単独の型検査も実行処理とHTTP処理が対象で、CVAT全体の型検査ではありません。

受入確認には専用タスクを使用し、Task、Job、画像の単独条件と組合せ、条件なし、入力途中の実行防止、タグとマスクの混在、画像の選択解除、Classification、間引き、削除フレーム、複数ページ、権限拒否、中止、保存エラー、利用者と組織の変更を確認します。小さいブラウザー画面で操作ボタンとスクロールを確認し、マスク変換が既定で有効であること、標準の自動アノテーションが変わらないこと、既存図形が残ること、異なる名前の属性と点を対応付けられることも確認してください。

# ONNXモデルの登録とCVATでの利用

この機能は、メンバーがブラウザーでONNXモデルを登録し、CVATのアノテーション画面から実行できるようにします。
モデルの前処理と後処理は `model.py` に記述し、共通の推論コンテナで実行します。
公開前に試験画像を使った推論を行うため、パッケージの検査と試験が成功した版だけがCVATに表示されます。

## 管理画面へのアクセス

管理画面はCVATと同じ公開URLの `/model-registry/` に配置します。
CVATへログインした状態で、画面上部のモデル管理リンクを開きます。
既存のCVATのログイン状態を利用するため、モデル管理画面でユーザー名やパスワードを再入力する必要はありません。
通常運用では、メンバー自身がSSH接続したり、管理者へ個人用トークンの発行を依頼したりする必要はありません。

CVATのリンクから開いた場合は、そのままモデル一覧を表示します。
セッションが失効している場合は「CVATへ戻る」から同じタブでCVATへ移動します。
接続エラーが表示された場合は「再試行」で状態を確認し、続く場合は管理者へ表示内容を伝えます。
アカウントの作成、パスワードの変更、ログアウト、利用停止はCVATで行います。
CVATからログアウトした場合やセッションが失効した場合は、次の操作でセッションを確認できない状態を表示します。

画面は一覧と登録に分かれます。
モデル一覧には、他のメンバーが公開したモデルの名前、説明、種類、作者、連絡先、公開状態が表示されます。
出力ラベルと変換設定は「詳細を見る」から確認できます。
連絡先は作者が明示して登録した場合だけ表示し、CVATに登録されたメールアドレスを自動公開しません。
自分のモデルについては、公開前の登録処理や失敗した登録も確認できます。

## 登録に必要なファイル

登録時には次のファイルを用意します。
個別ファイルをフォームへ指定する方法と、ファイルをZIPの直下へまとめる方法を使用できます。
補助Pythonモジュールを含む場合はZIPで登録します。

| ファイル | 内容 |
|---|---|
| `manifest.json` | モデル名、説明、作者への連絡先、重みのファイル名、出力ラベル、ポリゴン変換設定 |
| `model.py` | `ModelBase` を継承する `Model` クラスと前処理、推論、後処理 |
| `*.onnx` | 1個から16個のONNXファイル。全ファイルを `weights` へ記載します。 |
| `sample.png` または `sample.jpg` | 公開前の試験に使う画像を1枚 |
| 補助の `*.py` | 必要な場合だけ追加するPythonモジュール |

ZIP内に親ディレクトリを作らず、全ファイルを直下に置きます。
ONNXの外部テンソルデータ、追加の依存ライブラリ、独自演算子、任意のDockerイメージをパッケージへ指定する機能はありません。
重みを1ファイルに内包したONNXへ書き出し、共通ワーカーにある依存ライブラリで動くコードを用意します。
利用可能なライブラリは `requirements-worker.txt` と `requirements-worker-gpu.txt` で確認します。

ZIPの上限は2 GiB、展開後の合計は3 GiB、ファイル数は40個です。
各Pythonファイルは1 MiB以下、マニフェストは256 KiB以下、試験画像は32 MiB以下です。
画像はPNGまたはJPEGで、1600万画素以下とします。
ディレクトリ、リンク、暗号化ZIP、同名ファイル、ファイル名の大小文字だけが異なる重複は受け付けません。

## セグメンテーションの出力契約

セグメンテーションでは、ラベルごとの二値画像を重ねたNumPy配列を返します。
配列の形は `(N, H, W)` とし、`N` は `manifest.labels` の要素数、`H` と `W` は `predict` に渡された元画像の高さと幅です。
配列の0番目をラベル配列の0番目へ対応付けるため、ラベルIDの値や連続性で配列位置を決めません。

各画素の値は `bool` または整数の0か1にします。
確率値、0と255の画像、クラスIDを格納した二次元画像は受け付けません。
確率からの二値化、クラス選択、サイズの復元は `model.py` で行います。
背景用の配列は自動的に追加せず、背景も出力する場合だけラベル定義へ含めます。

ラベルは全て `polygon` にします。
異なるラベルの二値画像が重なることは許容しますが、同じラベルの接触した領域を別インスタンスに分ける情報はこの形式では保持しません。
最終的な出力は、各ラベルの連結領域ごとのポリゴンです。

```json
{
  "schema_version": 1,
  "name": "臓器セグメンテーション",
  "description": "RGB画像から臓器領域を抽出します。",
  "author_contact": "team-models@example.internal",
  "weights": ["model.onnx"],
  "labels": [
    {"id": 10, "name": "liver", "type": "polygon"},
    {"id": 20, "name": "vessel", "type": "polygon"}
  ],
  "polygon": {
    "min_distance_px": 2.0,
    "spacing_percent": 1.0,
    "min_area_px": 10.0
  }
}
```

この例では、返す配列の `result[0]` が `liver`、`result[1]` が `vessel` です。
二値化のしきい値をマニフェストや管理画面へ登録する項目はありません。
CVATからしきい値が渡されても、管理サーバーはそれを推論結果の選別に使いません。
検出モデルでも、必要なスコアによる選別を `model.py` に記述します。

`Model` は次のインターフェースを実装します。
`load` で `context.create_session("model.onnx")` を使ってONNXを読み込み、`predict` で画像ごとに処理します。
`image` はRGB順の `uint8` 配列 `(H, W, 3)`、`params` はログの追跡に使う `request_id` を持ちます。
CVATが範囲を切り出して送信した場合、切り出し後の画像を元画像として扱います。

```python
from registry.sdk import ModelBase, ModelContext, PredictParams

class Model(ModelBase):
    def load(self, context: ModelContext) -> None:
        self.session = context.create_session("model.onnx")

    def predict(self, image, params: PredictParams):
```

実行可能な作例は `examples/segmentation/` と `examples/segmentation-demo.zip` にあります。
作例は接続と出力形式を確認するためのもので、学習済みの認識モデルではありません。

## ポリゴンの形を調整する設定

ポリゴン変換の設定はモデルの版ごとに保存します。
登録フォームで指定するか、マニフェストの `polygon` へ記載します。
設定を変更して公開すると新しい版になるため、重みを変えずに変換設定だけを変更する場合もパッケージ全体を更新します。

| 設定 | 既定値 | 動作 |
|---|---:|---|
| `min_distance_px` | 2.0 px | 隣接頂点間の直線距離の下限です。最後の頂点と最初の頂点にも適用します。 |
| `spacing_percent` | 1.0 % | 元の外周の長さに対する頂点配置の間隔です。0から100の範囲で指定します。 |
| `min_area_px` | 10.0 | 除外する小領域の基準です。変換前の領域の画素数と変換後のポリゴン面積に適用します。 |

頂点配置の基準となる間隔は、`min_distance_px` と「外周の長さ × `spacing_percent` / 100」の大きい方です。
その間隔以上になるよう外周上へ等間隔に頂点を置き、隣接頂点間の直線距離が不足する点を取り除きます。
最小距離と周長比を両方0にした場合は、輪郭の方向が変わる点を使用します。

面積による除外では、最初に4近傍の連結領域の画素数を確認します。
変換後にもポリゴン面積を確認し、設定値より小さい図形を除外します。
画素中心の輪郭を使うため、画素数とポリゴン面積は一致せず、細い領域や小さい領域が除外される場合があります。

この変換は外周を出力し、穴を表現しません。
穴のある領域は、その外周の内側を塗りつぶしたポリゴンになります。
点を減らした結果が3頂点未満、面積0、自己交差となる領域も出力しません。
間隔を大きくすると小さい領域が消えることがあるため、用途に合う試験画像で設定を確認します。

返却できる二値配列は合計2400万要素以下、最終結果は2000図形以下です。
ポリゴンは1図形4096頂点以下、全図形の合計10万頂点以下とします。
上限を超える出力は推論エラーになるため、画像の大きさ、ラベル数、頂点間隔を合わせて調整します。

## 物体検出の出力契約

物体検出だけを行うモデルでは、ラベルを `rectangle` にし、`registry.sdk.Box` のリストまたはタプルを返します。
作例は `examples/detection/` と `examples/detection-demo.zip` にあります。

```python
from registry.sdk import Box

# class_id は manifest.labels に定義したIDです。
# xyxy は入力画像上の (左, 上, 右, 下) で、右端と下端は排他的です。
return [Box(class_id=10, score=0.92, xyxy=(12.0, 20.0, 80.0, 100.0))]
```

スコアは有限な0以上1以下の値にし、座標は画像の内側へ戻してから返します。
管理サーバーはスコアで検出結果を間引かないため、低スコアの除外と重複検出の抑制も `model.py` が行います。

既存コードとの互換性のため、`Box` と `Mask` を混在させたリストも受け付けます。
この場合は対応するラベルを定義し、`Mask` の二値画像だけをポリゴンへ変換します。
新しいセグメンテーション用の `(N,H,W)` 配列を返す場合は、ラベルを全て `polygon` に揃えます。

## 登録、更新、CVATでの実行

新しいモデルは登録画面から送信します。
サーバーはファイルを検査し、隔離したワーカーで読み込みと試験推論を行い、結果の形式も検査します。
処理が成功すると公開状態になり、CVATのモデル一覧へ反映されます。
失敗した場合はモデルの詳細画面から登録状態とログを確認します。

既存モデルを変更するときは、そのモデルの詳細画面から更新を開始します。
新規登録から送ると別のモデルになるため、同じモデルの版を追加する場合は更新操作を使います。
更新の試験に失敗した場合は、公開中の版を維持します。

CVATではAI実行画面で公開モデルを選び、モデルの出力ラベルとタスクのラベルを対応付けます。
セグメンテーションの結果は登録した設定で既にポリゴンに変換されているため、CVAT側でマスクからの追加変換を行う必要はありません。
更新後はモデルを選び直し、新しい版を使用します。

公開モデルの説明は他のメンバーも確認できますが、更新、削除、試験、版の操作、ログの閲覧は所有者と管理者だけが行えます。
モデルを削除すると全ての版の新規推論を拒否し、保存済みのCVATアノテーションは残ります。
実行中の一括アノテーションを完了させる場合は、その処理が終わってから削除します。
